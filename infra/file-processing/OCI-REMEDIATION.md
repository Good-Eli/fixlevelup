Grype reported unknown fix state there; the OpenSSL CNA records and [upstream advisory](https://openssl-library.org/news/secadv/20261117.txt) confirm affected ranges include 3.5.9 and point to 3.5.10. The advisory schedules the release for 1 December 2026; the official sampled Alpine `v3.24/main/x86_64` repository served only 3.5.9-r1 for both APKs. Do not transplant the old findings as exact scratch counts: scanner has `libcrypto` but no `libssl`; decoder contains its own static OpenSSL. The stdin-only worker has no socket or TLS server/client setup. This is useful reachability context for QUIC/TLS/DTLS/DANE issues, **not** proof that `libcrypto` parsing and certificate paths are unaffected.

The exact `clamscan` launcher still accepts only bounded stdin but runs parsers before decoder MIME enforcement; the MIME label is not evidence of the incoming byte structure. Binding findings came from the exact `libclamav` ELF dynamic symbol table and the scratch dynamic loader's `--list` output, not from scanner package metadata alone. Fix/reachability conclusions apply only to these fixed entry points and separate images, not arbitrary runs of Node, ClamAV, or FreshClam.
