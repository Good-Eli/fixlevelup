TECHNICIAN/TG (включая CUSTOM-TG) не получает effective P03. CITY требует действующего admin-city assignment; scope всех требуемых кодов **пересекается** на одном target. `AccessView.p03Permissions?: readonly P03Grant[]` отдельно от staff/geography. `withP03(proof, mode, required: readonly P03Capability[], target: P03Target, callback)` принимает либо COMPANY без cityId, либо CITY с точным cityId; для content item доверенный resolver на том же client устанавливает реальный persisted scope после проверки наличия кодов и до callback. Отсутствие operation grant — 403; непокрытый CITY, другой parent/type и невидимый объект — 404. Делегирование/расширение scope/назначение роли и расширение CITY при `adminAssign` требуют собственный GLOBAL того же кода под тем же RBAC lock; точный retained grant не новая выдача. Existing geography/role rules не заменяются.

Миграция [018 `20261122000400_settings_management`](../prisma/migrations/20261122000400_settings_management/migration.sql) добавляет в `foundation`:

- `p03_bootstrap_permissions(assignment_id uuid, permission_code, row_version integer DEFAULT 1, revoked_at, revoked_by)` PK `(assignment_id,permission_code)`. `issue_first_p03_permissions()` без аргументов, EXECUTE только migrator; под RBAC lock проверяет первичный bootstrap marker, точно исходное назначение, ACTIVE SYSTEM ADMIN и существующий web credential. Idempotent insert без оживления и без role grants. Fresh bootstrap вызывает в своей транзакции; recovery/login/reassign не вызывают. Runtime не может INSERT/DELETE/TRUNCATE; UPDATE только поля однонаправленного revoke с DB clock, actor, новым row_version. Не смешивать со старым geography issuer. Revoke источника не отзывает независимо записанные role grants.
- `p03_command_receipts(actor_id uuid, operation, key uuid, request_sha256, entity_id uuid, entity_version integer, revision_id uuid NULL, revision_version integer NULL, created_at)`; PK `(actor_id,operation,key)`; immutable, DB timestamp и column ACL. `operation` ровно 10 ключей `P03_COMMANDS`; revision-пара одновременно обязательна только для `referencePublish`, `contentPublish`, `legalPublish`, иначе обе NULL. Positive PostgreSQL int версии. Сырые payload, текст и provenance здесь не хранятся.
- Прежний `role_permissions_scope_check` сохраняет старые правила и добавляет CITY только для content/callback; catalog collision или scope drift не превращается в authority. Старые 001–017 неизменны. Несовместимость schema/catalog/issuer блокирует management routes (503), а `/health/ready` не обещает бизнес-готовность.

## 2. Wire и команды

Ниже пути относительно `/api/v1`. `GET` — ровно `{data,meta:{requestId}}`; JSON то же для команд. Versioned list добавляет `version` родителя и его ETag. Details используют version соответствующей identity/revision. Path IDs — UUID; query/body timestamps и response timestamps — ISO 8601 с зоной. Другие query keys, повтор query keys, неизвестные/серверные поля body запрещены. `limit` 1–200, default 50; `cursor` ≤1024 URL-safe символов.

URL→DB reference type: `callback_interval→CALLBACK_INTERVAL`, `payment_method→PAYMENT_METHOD`, `cancel_reason→CANCEL_REASON`, `decline_reason→DECLINE_REASON`, `request_source→REQUEST_SOURCE`. `?cityId=` mandatory on **every** callback route and forbidden on all other reference types. Content item never uses request scope; fallback changes consumption only. Legal uses REQUEST_PROCESSING/MARKETING, never ADDRESS_COVERAGE/consent events. Readiness excludes document IDs/text, source/policy refs, primary, global counts and `ready`; MARKETING is not a prerequisite. Only allowed publication uses plain editable form text with deliberate confirmation, not persisted draft.

Mutation header `Idempotency-Key` is one UUID. All non-create ops require a single strong `If-Match: "p03-vN"`; `N` positive integer up to 2147483647 (`p03-v0` only for read). Mutations return `data:{id,version}` except the three revision publications, which add `revisionId,revisionVersion`. `companyPublish` identifies the new company revision; bootstrap revoke identifies original assignment and exact source row_version. `ETag` always corresponds to receipt `version`; replay changes neither `data` nor ETag, returns 200 (first status `P03_COMMANDS[op].status`). No body/reviewer/actor claims in receipt. Existing geography keeps `geo-vN` and old routes; paging adds `pageInfo` without removing `items`/`version`. Full coverage GET stays complete/bounded or fails, not paginated.

Ordered writes: explicit RC → RBAC policy lock → checked web session/staff/role & capability → company advisory lock if needed → city → aggregate. Same client for all ports/auth/evidence. Before using a receipt, independently authorize the requested target and the receipt’s actual historical target in the same transaction: for create, resolve the created object by receipt `entity_id`; for publish and archive, resolve and authorize the original aggregate by receipt `entity_id`. Publication revision IDs and sequence come from the immutable receipt that was committed atomically with the revision and its evidence; replay does not perform a new revision-to-aggregate query. Check actual scope/city/type, parent, identity and current visibility, not just request fields. Archive permits authorized historical snapshots and receipts but not a new publication. Read receipt before CAS; an exact digest replays; stale new commands return 412. For operations other than `bootstrapRevoke`, a digest mismatch returns 409 only after both targets are independently authorized. For `bootstrapRevoke`, check authority for the requested code first; then any digest mismatch returns fixed 404 without receipt data, whether or not the original code remains visible. An exact digest still requires current GLOBAL of that exact code and verification of the original source assignment against the receipt before replay. SHA-256 canonical envelope `{v,actor,operation,target,key,expectedVersion,normalizedBody}` v1; canonical lower UUIDs, exact typed fields/normalized values, deterministic JSON key order, explicit `null` for no expectedVersion. No authorization/evidence hashing reuse for another actor/target. Domain plus fixed-enum/ID/version-only audit/outbox and receipt commit/rollback atomically. Revalidate with fresh DB `clock_timestamp()` after waits (including receipt SELECT) and after final write/SELECT before success. Lost COMMIT ACK: new RC/auth transaction, recover *only* identical receipt after rechecking current authority/target and after-read expiry; never auto-retry mutation.

## 3. Bounds, errors, delivery

Staff-web cookie and same-origin policy; mutations exact Origin, JSON UTF-8 and existing CSRF; reads reject supplied foreign Origin. Always `Cache-Control: no-store`. Canonical path + method choose pre-parse cap: POST legal publish 1 MiB, POST content publish 128 KiB, nested PUT geography coverage 64 KiB, everything else 4 KiB. Alias/prefix/other method never expands limit. Streaming bytes and 10-second absolute deadline before DB, compressed encoding denied. Fixed problem envelope is `{type:'about:blank',title,status,code,requestId}`; 400 malformed/invalid/missing I, 401 expired/missing session, 403 insufficient authority, 404 unknown/foreign, 408 deadline, 409 conflict or mismatch, 412 stale, 413 body limit, 415 encoding, 428 missing V, 500 safe internal failure, 503 not ready. No SQL/body text/references in problems or logs.

Keyset filtering including authorization, parent/type/city/scope and filters occurs before `LIMIT+1`; use `(code,id)` for coded identities, `(version,id)` for histories, stable ordered closed enums or IDs if no code/version. Cursor versioned/bound to exact normalized filter and parent; never authority. All lists ≤512 KiB serialized UTF-8, history summaries exclude bodies, addresses and source/legal basis; exact content ≤256 KiB, exact legal ≤2 MiB, exact company/reference ≤16 KiB; remaining P03 details/receipts ≤4 KiB. Validate bytes outside transaction, never return partial object at cap. Decode only after bounded response transport; exact decoder field checks fail closed. CRM uses no-store same-origin relative paths and same key/canonical body/version only for explicit retry with same live actor generation; clear editing state on session/actor change, no storage/log/toast of text.

Workspace uses no lifecycle scripts; `pnpm run p03:contracts` builds JS/declarations; `pnpm run p03:verify-contracts` checks schema/catalog parity, exact routes, minimal receipts and maximum response fixtures. API/Web build and typecheck explicitly build dependency; root test builds before Vitest. Decoder image recipe copies only the new manifest for frozen install, neither P03 source/dist nor new pins. Gate proof remains independent: frozen strict-peer graph, real Nest/isolated PG, browser same-origin HTTPS smoke, P03-04 regression, final Astra audit and separate owner acceptance.
