## 1. Матрица авторизации и операционная граница

Все коды non-protected, `module = first segment`, active registry; 021 не вставляет role grants, personal grants или доменные значения. Переиспользуется действующий staff-web proof (cookie/Origin/CSRF), роли/назначения, RBAC advisory lock, нерекурсивные command ports 01/02. P03 codes, issuer, receipts, geography и wire contracts не переименовываются. Условие роли **и** capability обязательно; отсутствие P04-кода в P03 не означает право.

| Коды/операции | SYSTEM ADMIN web | SYSTEM MANAGER или CUSTOM-web (с web marker) | Техник/TG/неактивный |
|---|---|---|---|
| `catalog.read` — COMPANY typed categories/brands/models/faults/item/mapping/identities/history; `catalog.manage` — create, publish, archive | matching GLOBAL read, для write дополнительно manage | Не разрешено даже при malformed stored grant | Нет |
| `pricing.rules.read` — COMPANY rule definitions; `pricing.rules.manage` — create/archive definition | matching GLOBAL read, для write плюс manage | Нет COMPANY доступа | Нет |
| `pricing.read` — CITY fixed prices, rule versions, policy, estimate, city/label discovery; `pricing.manage` — publish/replace/close и estimate create/archive | GLOBAL либо точный CITY с действующим admin-city assignment; write = пересечение read и manage в одном target | Только явный CITY и действующее admin-city assignment; write = пересечение read/manage в точном городе | Нет |
| `content.externalreviews.read`, `.manage`, `.publish` — COMPANY Avito entries/history, create/archive, publish соответственно | matching GLOBAL; create/archive read+manage, publish read+manage+publish | Нет | Нет |

CITY pickers требуют собственный `pricing.read`, список только собственных разрешённых городов и безопасных опубликованных labels, не company history. Клиентский cityId — цель, не authority. Нет догадки по P03, `primary_city`, сырому actorId или browser role. Только SYSTEM ADMIN с существующим `roles.permissions.manage` и собственным P04 **GLOBAL того же кода** делегирует/усиливает grant; точное сохранение уже видимого grant другой роли не выдача. Назначение роли и добавление CITY административного назначения требуют такого же exact GLOBAL по каждому расширяемому P04-коду. При изменении общего P04 role grant нельзя ограничить его последствие одним текущим сотрудником. Невозможность косвенного усиления через подстановку роли/территории проверяется под RBAC lock. Редактор ролей отображает полученные P04 источники, но UI не является проверкой. Для общей роли изменения распространяются на её текущих/будущих участников.

- `p04_bootstrap_permissions`: персональный GLOBAL источник только на первоначальное проверенное `staff_role_assignments.id`, PK `(assignment_id,permission_code)`, revokedAt/by и ровно один необратимый переход. SQL issuer migrant-only без аргументов и без startup/migrate/recovery hook; проверяет оригинальный bootstrap proof из P03 под RBAC advisory lock. Позитивная выдача вызывается **только fixture** явно — `current_database()` ровно `fixlevelup_configuration_test_[a-f0-9]{24}` или `fixlevelup_p04_browser_test_[a-f0-9]{24}`, RC, `current_user=fixlevelup_migrator`. Скрипт фикстуры additionally checks its isolated database and connection identity. Live/dev name не допускается, runtime не получает EXECUTE/INSERT/UPDATE/DELETE/TRUNCATE, no live bootstrap или production конфигурация даже при наличии функции. Owner-only fixture revoke под тем же lock; no reissue (`ON CONFLICT DO NOTHING`, один источник на actor/code) после revoke, replay, login или reassign. Нет P04 персонального web-editor или произвольной issuance. Этот тестовый issuer **не** готовность дать реальные права; будущая live выдача требует собственного решения владельца.
- DDL на `role_permissions` расширяет только CHECK CITY allowlist двух `pricing.*` кодов, новый invoker trigger проверяет exact role/scope/module; другие коды/триггеры прежние. P03 readiness принимает ровно известные физические контракты 018 и 021 (нельзя выключить проверку old constraint), P04 feature gate separately checks required tables, fields/catalog/guards and no broadened runtime issuer ACL. ## 2. API v1: закрытые именованные операции

Префикс `/api/v1`. COMPANY пути не принимают cityId или raw scope; все names/fields от route binding. Идентичность: `list/get` и только именованные `create`, `publish`, `archive`. Ни DELETE/PATCH произвольной таблицы, ни записи price из карточки SKU. История отдельными bounded list и exact id, immutable original payload; closure — separate `effectiveUntil`. Методы `GET` и `POST` одной версии. Org single-company.

| Семейство | GET | POST |
|---|---|---|
| `/catalog/{categories,brands,models,faults,items}` (`catalog.*`) | `base`, `base/{id}`, `base/{id}/versions`, `base/{id}/versions/{versionId}` | `base` create, `…/{id}/versions` publish, `…/{id}/archive` |
| `/catalog/fault-service-mappings` (`catalog.*`) | `base`, `base/{id}` (immutable pair/first publication) | `base`, `…/{id}/publish`, `…/{id}/archive` |
| `/pricing/rules` (`pricing.rules.*`) | `base`, `base/{id}` | `base` create, `…/{id}/archive`; no company tariff values |
| `/pricing/cities` (`pricing.read`) | list safe `{id,code,name}`, `/{cityId}/categories`, `/{cityId}/items` and `/{cityId}/rules` safe minimal active labels (so CITY may manage its own data without COMPANY read) | — |
| `/pricing/cities/{cityId}/items/{itemId}/price-versions`; same prefix `/rules/{ruleId}/versions`; same prefix `/policy-versions` (`pricing.*`) | list history `{version,items,pageInfo}`, exact `/{versionId}` | `base` publish, `base/{versionId}/close`, `base/{versionId}/replace` |
| `/pricing/cities/{cityId}/public-estimates` (`pricing.*`) | `base`, `/{estimateId}`, `/{estimateId}/versions`, `/{estimateId}/versions/{versionId}` | `base` create, `/{estimateId}/archive`, `/{estimateId}/versions` publish, `…/versions/{versionId}/close` or `/replace` |
| `/content/external-reviews` (`content.externalreviews.*`) | `base`, `/{id}`, `/{id}/versions`, `/{id}/versions/{versionId}` | `base` create typed PROFILE/REVIEW, `/{id}/versions` publish, `/{id}/archive` |
| `/pricing/readiness` (`pricing.read`) | Scope-limited required counts not exposed, paged cities with only founded fixed/policy statuses `CONFIGURED` / `MISSING`, no auto-ready/public or policy content; local catalog knowledge vs required full business configuration | — |

Canonical P03 zones/FAQ/city contacts unchanged, no catalog alias needed for a previously unimplemented route. Filter: `limit` default 20/max50, `cursor` ≤512 base64url, `includeArchived` only identity lists/closed staff history by explicit query (defaults false). Optional explicit enum `kind` on catalog items/rules/Avito; actual parent filtering before LIMIT. Ordering `(code COLLATE "C",id)` coded, `(version DESC,id DESC)` history, `id` for mapping. Cursor contains exact route/normalized query shape, parent IDs and authorized city target binding; not credential, reauthorize every request. Read history/receipt requires same IDs/parent/kind/city, not just path. Body exact typed 01/02 fields with necessary parent identifiers/actor/expectedVersion exclusively bound from URL/security headers; immutable start/close fields already in 01/02. `close` body `{at}`, `replace` new amount/rule/policy/etc + `{at}`, not free `validFrom`. Archive/publish mapping use `{}`. Neither money input nor producer-issued adjustment evidence is accepted by an endpoint that is not an explicit management price publication. `GET` returns `{data,meta:{requestId}}`, mutation additionally positive `{id,version[,revisionId,revisionVersion]}` projected only. Stable mapper for SQL price/range fields returns canonical minor strings. I/V headers: one UUID `Idempotency-Key`; strong canonical `If-Match: "p04-vN"` required for all except identity create. Allow `N=0` only for **first publish** fixed/rule/policy stream (reflect empty list version 0), not a persisted receipt or any existing mutation; 1…2147483647 elsewhere. POST create/publish/replace→201, close/archive→200, exact replay→200 with same `data` and ETag.

### Command proof and strict transport

Operation IDs use resource prefix + action: `category|brand|model|fault|item` + `List/Get/Versions/Version/Create/Publish/Archive`; `mapping` + `List/Get/Create/Publish/Archive`; `rule` + `List/Get/Create/Archive`; `cityList`, `cityCategories`, `cityItems`, `cityRules`, `pricingReadiness`; `fixed|ruleVersion|policy` + `List/Get/Publish/Close/Replace`; `estimate` + `List/Get/Create/Archive/Versions/Version/Publish/Close/Replace`; `avito` + `List/Get/Versions/Version/Create/Publish/Archive`. Catalog item params in this family use `{id}`, money nested paths `{cityId}`, `{itemId}`, `{ruleId}`, `{estimateId}`, `{versionId}` exactly. All mutations share receipt columns `actor_id,operation,key,request_sha256,city_id,subject_id,target_version_id,entity_id,entity_version,revision_id,revision_version,created_at`; `subject_id` saves persisted created identity for identity-create, immutable path ID for identity and city nested commands, `city_id` itself for policy. `target_version_id` present exactly on close/replace. Archive KIND/target existence read verifies persisted subject; recent archive does not delete historical authority. `issue_p04_synthetic_permissions()` is the only issuer (no args, migrator only); fixture revocation uses guarded owner SQL. For the bare catalog directory create request Kind derives from path, with `code` and required `categoryId`/`brandId` for relevant variants. For item create/publish require its typed `kind`; estimate category supplied only on create; Avito create `{kind,code,profileId?}`, publish `{title,sourceUrl,permissionRef,sourceDate?,excerpt?,rating?}` and body fields validated against stored `kind` (optional `kind` is not accepted on publication).

- Canonical operation ID from exact supported method+path. No case/trailing/encoded path alias bypass (Express may dispatch aliases; P04 strict route matcher rejects them too). Buffer cap before parsing: standard 16 KiB, ONLY exact policy publish/replace 64 KiB, avito 12 KiB, absolute 10s unchanged, strict UTF‑8 JSON and no compressed. P04 parser uses bounded duplicate-aware codec before any token loss, including escaped keys; reject extra/unknown fields or query parameters. P03 keeps its existing caps and parser. Valid numeric decisions: integers canonical, money strings; no precision loss/`Number` for money. Response caps list 256 KiB, exact details 64 KiB (policy), receipt 4 KiB. Serialize and verify size before sending, no-store every status. Envelopes preserve the old error surface: 400 invalid, 401 session, 403 missing code/origin/CSRF, 404 unknown/foreign, 408 timeout, 409 conflict, 412 stale, 413 size, 415 encoding, 428 missing V, 500 safe internal, 503 not-ready or unknown commit. No raw SQL/body/secret logs.
- Order: RC → RBAC policy lock → current staff/web/role/capabilities/target → catalog shared fence (read) or exclusive (mutate) where applicable → city row/catalog under data port → receipt/evidence and domain commits in one client. Read receipt by `actor_id,operation,key` before CAS; `p04_command_receipts` has closed mutation operation code set, scoped actual target/city and canonical digest; minimum positive receipt projection and DB created time. A version command stores aggregate own `id` (city stream id for version receipts) and canonical target route IDs independently (primary subject may be itemId, ruleId, cityId etc). Same target exact replay returns previous receipt after revalidation even if archive/supersession stale, not changed write; `409` digest diff **only** when both actual requested and historical receipt target are currently visible/authorized with the exact codes. No issuer route/receipt in P04. Lock-controlled scope always re-evaluated for original and requested targets before receipt/CAS; empty/fake stream does not become authority. Exact digest uses same parsed immutable command (canonical UUID, nulls/text/array ordering per operation, normalized preconditions and explicit target canonical fields). No unnormalized mutation body re-read after hashing. Store no business body. If COMMIT unknown (discard broken connection), no auto mutation retry; exact explicit request retry with live actor/key/target/body/If-Match only. Before effect after target/receipt/fence wait and just before reply/COMMIT, recheck session expiry/revocation and scope under policy lock; errors after potential waits also recheck before exposing stale/conflict or stored result. SAVEPOINT rollback removes domain/audit/outbox/receipt on failure, do not mask internal driver/evidence. P03 security and fault guarantees retained.
- Single source OpenAPI 3.1 + generator for shared typed client, checked generation without external deps. Add isolated entry `@fixlevelup/p03-contracts/p04` (existing workspace package/build name kept; no changes to P03 exports). Authoring artifact documents actual fields, enums, required I/V, cap/status/security, examples and pagination; generated runtime modules/types/OpenAPI build output ignored (not committed), generated compatibility checks and `p04:verify-contracts` from source. Shared client uses injected transport; actual relative same-origin/no-store browser transport and UI P04-04. HTTP regression tests enumerate registration against generated operation set and assert runtime DTO/security. Module source and generation build order frozen, no packages added.

### Hand-reviewed Avito entries

`external_reviews` stable UUID/code/kind PROFILE/REVIEW. PROFILE parent null; REVIEW requires `profile_id` typed composite FK to PROFILE. Pointer to own immutable `external_review_revisions`. Published revision holds `id,entry_id,kind,version,title,source_url,source_date,excerpt,rating,permission_ref,profile_revision_id,reviewed_by,published_at`. `PROFILE` has URL/title/evidence ref with `source_date/excerpt/rating/profile_revision_id` null; `REVIEW` has date `YYYY-MM-DD`, plain excerpt ≤1500 code points, rating null or integer 1…5, validated explicit permission ref ≤200 and original reviewed live profile revision exact FK. Profile archive makes fresh review publication fail; exact historic versions still inspectable. Review publish uses server review actor/time, references reviewed profile revision (no HTTP request). Normalize/accept only canonical `https://avito.ru/…` or `https://www.avito.ru/…` ASCII, no explicit port including `:443`, query, fragment, backslash, userinfo, control, escaped/decoded ambiguous path, network retrieval or redirect. Paths bounded allow simple safe path segments; trim/case behavior fixed in exact decoder. HTTPS/host allowlist is **format**, not verified content or permission. No public profile projection. Immutable revision/read-and-publish/archive uses same catalog fence and audited write transaction with approved source/one-way union. No grants to manage live reviews.
