# P05-02: Form Session Foundation (S2) - Contract

## Overview
P05-02 implements the pre-submit form-session contour of P05 (schema profile S2): migration `20261124000100_form_session_foundation` (023), additive over 022, plus the seven exact public F routes of P05-PLAN §4.1/§6.3 under `/api/v1/public`. No clients, requests, submit-edge, receipts, phone events, staff bridge or callback/repair HTTP are created here; those remain P05-03/P05-04. The P03 anchor `foundation.request_sessions` (013) stays the only F anchor and the only F secret: 023 adds opaque browser groups, their thin membership mapping and bounded throttle counters only.

Exact wire surface (canonical method + path only; no alias, trailing slash or query string; every response carries `Cache-Control: no-store`):

| Method and path | Success | Notes |
|---|---|---|
| `POST /api/v1/public/form-session/browser` | `200 {groupId, expiresAt, created}` | Group bootstrap; `Set-Cookie` only on creation; requires a non-simple same-origin marker header |
| `POST /api/v1/public/form-sessions` | `201 {sessionId, intakeCityId, intakeCityVersionId, timezone, createdAt, expiresAt, csrfToken, csrfExpiresAt}` | `X-Form-Session-Id` + proof `Set-Cookie`; city comes from the SINGLE_CITY resolver, never from the body |
| `POST /api/v1/public/form-session/csrf` | `200 {sessionId, expiresAt, csrfToken, csrfExpiresAt}` | Read-only reissue for a live own anchor; never extends the anchor |
| `POST /api/v1/public/form-session/revoke` | `200 {revoked}` | Addressed `Max-Age=0` for exactly that cookie; a second revoke discloses nothing |
| `GET /api/v1/public/legal-documents/{kind}` | `200` public document | Only the current published REQUEST_PROCESSING `POLICY`/`CONSENT_FORM`; no operator-only fields |
| `POST /api/v1/public/form-session/consents` | `201` first write, `200` exact replay | GIVEN/REVOKED evidence through the existing legal ports; mandatory `Idempotency-Key` |
| `POST /api/v1/public/coverage/check` | `200 {cityId, cityVersionId, districtId, outcome: 'AREA_REVIEW_REQUIRED', hints}` | District id of the own city only; never `IN_ZONE`; an address in the body is refused |

Refusals are RFC 7807 `application/problem+json` with a closed five-key body and are classified as: malformed/PII `400`, missing or dead proof `401`, origin/CSRF/capability `403`, foreign target `404`, business/state `409`, over a JSON contract cap `413`, unsupported media `415`, semantic `422`, quota `429`, safe unavailability / not ready `503`.

## Scope & Compliance
1.  **S2 Schema Foundation**: Implemented `form_browser_groups`, `form_session_group_memberships`, and `form_throttle_buckets` with strict immutability and guards per §6.3.
    - `form_browser_groups` stores an opaque id, a SHA-256 hash of the 32-byte group secret, and DB `created_at`/`expires_at`. It is immutable history: the guard refuses `UPDATE`/`DELETE` with SQLSTATE 23514, pins `created_at` to `clock_timestamp()` even on an owner `INSERT`, and a separate trigger refuses `TRUNCATE`. No PII and no cookie value is stored.
    - `form_session_group_memberships` is the thin 1:1 mapping `session_id` → `group_id`. `session_id` **is** the P03 `request_sessions.id`, i.e. the public F selector; there is no second anchor id, secret hash, expiry or revoke here. The INSERT guard requires an existing browser group, an existing live (unrevoked, unexpired) P03 anchor, and an anchor expiry not later than the group expiry; `UPDATE`/`DELETE`/`TRUNCATE` are refused.
    - `form_throttle_buckets` is a bounded fixed-window counter (`kind` in `SOURCE|GLOBAL|ANCHOR`, HMAC `key_hash`, `window_started_at`, `window_seconds`, `hit_count`), not policy and not PII. `hit_count` can only stay or grow, identity/window columns are immutable, `DELETE`/`TRUNCATE` are refused, and the unique key is `(kind, key_hash, window_started_at)`.
    - The runtime role receives exact column grants only (no `DELETE` anywhere, no `UPDATE` on groups/memberships, `UPDATE(hit_count)` only on buckets); all guard functions are `SECURITY INVOKER` with a fixed `search_path`, not executable by runtime or `PUBLIC`. A direct owner write therefore cannot bypass the DB clock or the cross-table expiry rule.
2.  **S2 Profile, Operator Preflight and One-time Admission**: `RuntimeDatabase` is pinned to the S2 SHA-256 fingerprint `978d2d36f4c0c385492b2478cfe1663b97ca3a18fa890e53fb97c3c0ffd15a45`; the S1 fingerprint `6626dcc51bf6f5c59da82b1d1d5e05e55bb7757d77ce9963d1b182d90d3dde27` is unchanged and does not include 023 objects.
    - The S2 probe fingerprints the exact physical contract of 023: the three tables (owner, kind, persistence, RLS flags), every column (attnum, type, typmod, nullability, identity, generated, default), constraints, indexes, every non-internal trigger, the four guard/history function bodies (SHA-256 of `prosrc`), the exact runtime column grants, the per-privilege table-level ACL shape, the absence of `PUBLIC`/third-party ACL, the **working state** of every internal FK constraint trigger keyed by stable constraint identity (`tgenabled`, so disabled FK enforcement moves the hash), and the exact function ACL entries of all four guards. The pinned-hash list fails closed when empty; the probe is single-flight and requires the guarded runtime pool (i.e. enabled auth and a completed admission).
    - The S2 admission profile is exact and positive in both directions: legacy readiness + the separate P04 catalog gate + `requestIntakeReady()` (022) + `formSessionReady()` (023). S1 additionally requires the positive absence of every 023 object (a full or half-destroyed S2 database cannot masquerade as S1); S0 requires the absence of both 022 and 023 objects. A correct identity plus a live witness does not admit a drifted schema.
    - The operator preflight is out of band (P05-PLAN §7): the trusted release/test preflight verifies the full migration history on its own connection with the migrator credential against the pinned artifact manifest, and runtime never reads `_prisma_migrations` and has no history ACL. The Ed25519 launch proof binds issuer generation, launch nonce, consumer kind, instance, channel, artifact digest, endpoint, database/OID/role/schema, profile, history manifest digest, physical contract digest, witness and expiry; the expiry is stored in the registry row and signed in the payload.
    - Admission is a one-time CAS `ISSUED → CONSUMED`: the registry row is consumed by a single conditional `UPDATE` that also requires the exact digest, the exact verified consumer/instance/channel binding and `clock_timestamp() < expires_at`, and only a confirmed `COMMIT` returns success. Two processes with the same proof produce at most one winner; an expired row stays `ISSUED` forever and can be consumed by nobody; there is no revoke before TTL; re-issuing the same generation/nonce is `ALREADY_ISSUED`; an unknown COMMIT outcome closes the waiting channel without a second admission. The lifecycle and its residual limitations are recorded in [P05-02-PREFLIGHT](P05-02-PREFLIGHT.md).
    - `503 NOT_READY` semantics: after exact-route matching, every F route runs the readiness gate (`requestIntakeReady()` and `formSessionReady()`) before Origin, body or cookie handling and before any business effect. The gate is closed when 023 is not applied, when any fingerprinted 023 object is missing or modified (table/column/constraint/index, a disabled guard trigger, a disabled FK constraint trigger, a weakened CHECK, an extra `UPDATE`/`DELETE`/`PUBLIC` grant, a modified guard body or function ACL), when the S1 gate is false, when the probe errors or the runtime pool is unavailable, and when auth is disabled. The response is `503` with problem+json `code: "NOT_READY"` and `no-store`; no business transaction is opened and no partial write can survive. `503` is also the safe answer for a response that exceeds its route cap, instead of a truncated body or an untyped `500`.
    - The database clock is the only time authority: group/anchor/CSRF expiry and throttle windows are computed and compared with `clock_timestamp()`, never with the host clock; the clock is re-sampled after lock waits and before `COMMIT`.
3.  **Transport, Cookies, Throttling, Idempotency and Fail-safety**: CSRF, cookie protection (`__Host-` prefix), exact Origin, and advisory coverage are enforced as follows.
    - **Transport and same-origin.** Every mutating route requires the exact configured `Origin` (missing or different → `403`); the public legal-document GET tolerates an absent `Origin`, but any supplied value must match. Duplicated security-relevant headers (`Origin`, `Cookie`, `Authorization`, `Content-Type`, `Content-Length`, `Transfer-Encoding`, selector/CSRF/idempotency/bootstrap/conditional headers) are `400` before any effect, on all seven routes including the GET. JSON bodies are capped before parse at 16 KiB / depth 16 / 256 nodes (over a cap → `413`), decoded with a duplicate-aware grammar and fatal UTF-8 (duplicate members, lone surrogates, invalid UTF-8, non-object root → `400`); a non-JSON type is `400` and `application/json` with an unsupported parameter is `415`. Protocol caps: 4 live anchors per browser group (counted from the database, not from the cookie jar), 8 presented proof cookies (`413` beyond; a request already carrying 8 cannot issue a ninth → `429`), 8 KiB `Cookie` header, 16 KiB JSON responses and a 1 MiB legal-document response (a response over its cap → `503`). No query string is accepted on any route.
    - **Cookies (conservative `__Host-` policy).** Names are `__Host-fixlevelup_fgroup` (browser group, 43-char base64url) and `__Host-fixlevelup_f_<uuid>` (one proof per anchor, the uuid is the selector). Every `Set-Cookie` carries exactly `Path=/; Secure; HttpOnly; SameSite=Strict` and never `Domain`, so the browser cannot widen the cookie. Values are opaque: no percent-decoding, no unquoting, no normalisation; a duplicate cookie name, a non-canonical selector or a wrong secret length is `400`. `Max-Age` is the **floor** of the true remaining DB lifetime (never `max(1, …)`), so the cookie can never outlive its database row; the hard protocol bound is 7 days. With less than one second of DB lifetime left **no credential is issued at all**: a confirmed exact expired own group cookie yields `401` with `Max-Age=0` for that one cookie only, an issue under a sub-second group yields `401` with the group cookie cleared, and a sub-second anchor remainder is refused with `409`. `Max-Age=0` is emitted only for a provably dead own cookie (revoked or expired exact selector); a foreign/unknown cookie is never cleared (no oracle), an unknown presented group cookie is never silently replaced, and a CRM session cookie is ignored, never honoured as an F proof and never cleared. The raw `Cookie` header is bounded to 8192 bytes and 8 proof cookies before parsing (`413` beyond), and an `Authorization` bearer is refused (`401`) as never being an F credential.
    - **CSRF.** The mutation proof is a stateless HMAC `P05_F_MUTATE` over key id, selector, F secret and an absolute millisecond expiry (`keyId.selector.expiresAtEpochMs.mac`), compared in constant time. A key id containing `.` is rejected at construction (issue/verify grammar must be one-to-one); key rotation invalidates old proofs; a proof may never outlive its anchor; the expiry is judged on a DB clock sampled after the anchor lock.
    - **Throttling.** Fixed-window counters are charged in autocommit **before** the business transaction, so rejected attempts still count and a quota refusal cannot roll the counter back. Three kinds: `SOURCE` (a shared budget per source socket address for all F operations from it), `GLOBAL` (one shared budget per window, checked first), `ANCHOR` (per proven F session). The single-statement atomic upsert uses `ON CONFLICT (kind, key_hash, window_started_at) DO UPDATE … WHERE hit_count < maxHits`: it is saturating — at the budget the row is not updated and no row is returned, which maps to `429 QUOTA`, the counter stays exactly at `maxHits` and **no new bucket rows are created while the window is saturated**; an exhausted `GLOBAL` budget stops before `SOURCE` is charged, so it allocates no source rows either; `ANCHOR` is charged only after the anchor proof, so an unknown or foreign selector never allocates ANCHOR rows or consumes the owner's per-session budget. The raw source is never stored: the key is HMAC-SHA256 with a dedicated throttle secret distinct from the CSRF secret. A JSON-contract overflow (`413`) and a rate-limit refusal (`429`) are never conflated.
    - **Idempotency.** Consent mutations require `Idempotency-Key`: a canonical lowercase UUID. Missing, malformed, uppercase, non-dashed or duplicated headers are `400` **before** the F proof checks. The header is accepted only by the consent route: all other six F routes (`browser`, `form-sessions`, `csrf`, `revoke`, `coverage/check` and the legal-document GET) refuse a presented `Idempotency-Key` with `400`. The key is bound to the F session and to the exact intent: it must equal the body `evidenceRef`, and `consent_records` is append-only with `unique(session_id, evidence_ref)`. A first write answers `201` with `replayed: false`; an exact replay of the same key and intent answers `200` with `replayed: true`, the **same** `evidenceId` and no second row; the same key with another intent (another document version, a REVOKED supersede, another header value) is `409 CONFLICT`, never a second event and never a replay of the first; the key is scoped to the session, so the same key in another live F session is an independent event.
    - **Fail-safety.** PostgreSQL/driver/socket failures are classified as operational (`55P03`, `57014`, `40001`, `40P01`, `57P0x`, `08xxx`, `ECONNRESET`/`ETIMEDOUT`/`EPIPE`/connection-loss messages, admission denial) and become `503 UNAVAILABLE` → HTTP `503 NOT_READY`, never an untyped `500`. An unknown `COMMIT` outcome (e.g. `ECONNRESET` while `COMMIT` is in flight) means the transaction may or may not be durable: no `ROLLBACK` is attempted (it could mask the real state), no automatic retry or extra write is performed, the connection is discarded from the pool, and the client receives `503`. Duplication is excluded by construction: an exact retry with the same `Idempotency-Key` either replays the committed event (`200 replayed: true`) or, if that `COMMIT` actually aborted, creates the single event (`201`); the unique `(session_id, evidence_ref)` makes a second evidence row impossible. Revoke has a late-expiry guard: if the anchor expires while the revoke is being written, the whole transaction (revoke + audit) rolls back and the client gets `401` with the addressed `Max-Age=0`, never a successful revoke committed past the anchor lifetime.
    - **Coverage advisory.** The district is resolved only within the anchor's intake city; an unknown and a real foreign-city district return the identical `404` (no oracle), hints are capped at 64 (an over-cap mapping is refused, never truncated), and the outcome is always `AREA_REVIEW_REQUIRED` — district mapping is not address proof and never sets `IN_ZONE`. A city/version change under a live F session answers `409` on consent and coverage, and the CSRF reissue still works (it is not the conflict surface).
