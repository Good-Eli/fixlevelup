## Совместный интерфейс реализации

Миграция: `20261121000400_settings_legal_references` (013). Все таблицы в `foundation`. UUID генерирует сервер, даты — timestamptz(6), история запрещает UPDATE/DELETE/TRUNCATE. Нет seed, новых автоматически выданных прав или записи в рабочую dev БД.

### Настройки

Общий helper `acquireCompanySettingsLock` использует transaction advisory lock `(734305,1)` до строк города и до чтения последней ревизии. Его берут и publisher настроек, и cityActivate/citySetPrimary/cityDeactivate; это сохраняет порядок блокировок и не допускает потери concurrent ревизии. Географическая ревизия может сохранять неизвестные company-поля NULL и не означает готовности company policies; полная публикация company-настроек требует всех полей.

Дополнить существующие `business_settings_versions` nullable полями `operator_name text`, `operator_registration_id text`, `operator_address text`, `legal_review_ref text`, `security_policy_ref text`, `retention_policy_ref text`, `upload_policy_ref text`. NULL означает неизвестно. Непустые значения ограничены по длине. Существующие ревизии сохраняются; новая географическая ревизия primary копирует поля последней ревизии. Новая полностью настроенная ревизия публикуется только внутренней типизированной командой с ожидаемой последней version; пустые/неизвестные поля отклоняются. Ссылка на политику — обязательная reviewed provenance, не сама реализация upload/retention/security policy. City timezone/contact/hours читаются только из `service_city_versions`. Readiness сообщает конкретные отсутствующие поля и текущие purpose-specific документы; это readiness данного среза, не приём заявок/production.

### Справочники

`reference_entries`: id, type varchar(32), scope varchar(16), city_id nullable, code varchar(64), row_version default 1, current_version_id nullable, archived_at nullable. Типы: CALLBACK_INTERVAL (строго CITY), PAYMENT_METHOD/CANCEL_REASON/DECLINE_REASON/REQUEST_SOURCE (строго COMPANY). Unique company(type,code) / city(city_id,type,code), unique(type,id), unique(type,id,current_version_id) target по необходимости. Стабильные id/type/scope/city/code; БД увеличивает row_version.

`reference_entry_versions`: id, entry_id, type, city_id nullable, version, label text, valid_from, valid_until nullable, source_ref text, reviewed_by staff FK, published_at default now, city_version_id nullable, start_minute/end_minute nullable. CALLBACK_INTERVAL имеет city_id/city_version_id/start/end (0 <= start < end <= 1440), same-city version FK. Другие типы не имеют interval/city полей. Unique(entry_id,version), unique(type,entry_id,id), composite(type,entry_id) FK. Current pointer того же entry/type; archived entry не выбирается для нового использования. Snapshot возвращает exact version/label/type/source/scope; архивирование не меняет прошлую ревизию. `city_version_id` справочника — provenance создания; timezone использования берётся из явно переданного trusted intake/visit city version того же города, с `timezoneCityVersionId` источника в DTO (`service_city_versions.id` из прочитанной строки, не echo ввода). `versionId` остаётся ID ревизии справочника; `provenanceCityVersionId` — прежний источник создания. Для COMPANY оба поля `timezone` и `timezoneCityVersionId` равны NULL. Эффективность проверяется на переданное/DB время, без неявного company fallback.

### Контент

`content_blocks`: id, code varchar(64), kind varchar(16) FAQ/FACT/SEO, scope COMPANY/CITY, city_id nullable, allow_company_fallback boolean default false, row_version default 1, current_revision_id nullable, archived_at nullable. Stable identity/scope/type; XOR CHECK scope/city, separate unique company(code) WHERE scope=COMPANY и city(city_id,code) WHERE scope=CITY. Без копии contacts/hours/timezone. `content_block_revisions`: id, block_id, version, title text, body text, source_ref text, reviewed_by staff FK, published_at default now. Unique(block_id,version), unique(block_id,id), current pointer composite FK. Все ревизии immutable, непустые title/body/source. Внутреннее publish = insert revision + CAS pointer. Effective resolution city first; company fallback лишь если company block явно разрешает fallback, с provenance scope/city/block/revision/source_ref. Legal/retention/security не переопределяются через контент.

### Документы и согласия

Purpose enum vocabulary: REQUEST_PROCESSING, ADDRESS_COVERAGE, MARKETING. Это отдельные цели; наличие одного согласия не разрешает другую. Marketing не обязателен для request processing. ADDRESS_COVERAGE — только зарезервированное слово для synthetic proofs, без реального документа, seed, маршрута или live-включения до решения Q02. Юридические документы company-wide.

`legal_documents`: id, purpose varchar(32), kind varchar(24) POLICY/CONSENT_FORM/OPT_IN_NOTICE, unique(purpose,kind), row_version default 1, current_version_id nullable. Stable purpose/kind; row_version увеличивает БД. Политика и текст согласия одной цели — разные документы; GIVEN принимается только для CONSENT_FORM.
`legal_document_versions`: id, document_id, purpose, kind, version, title text, body text, checksum varchar(64), legal_basis text, source_ref text, reviewed_by staff FK, published_at default now. Unique(document_id,version), unique(document_id,purpose,id), composite FK к parent document/purpose/kind. checksum SHA256 UTF-8 body проверяется БД. Непустые обязательные поля. Immutable. Current pointer same document/purpose.

`request_sessions`: id, secret_hash varchar(64) unique, intake_city_id, intake_city_version_id, created_at default now, expires_at, revoked_at nullable. Только минимальный pre-submit anchor, без имени/телефона/адреса/request/customer. Composite same-city version FK. Expiry задаёт вызывающий trusted policy, без TTL по умолчанию; expires_at > created_at. Stable identity/hash/city/created/expiry, разрешён только однократный revoke. Это не публичная аутентификация F; внешний route/session issuance в P05. Минимизация/cleanup и рабочие сроки требуют Q13.

`consent_records`: id, session_id FK, document_id, document_version_id, purpose, action GIVEN/REVOKED, legal_basis text, source varchar(32) FORM, evidence_ref uuid, occurred_at default now с принудительным DB clock в trigger, supersedes_id nullable (точный GIVEN, который отзывается). Composite document/version/purpose FK; legal_basis совпадает с immutable doc. Append-only events. REVOKED ссылается на GIVEN того же session/purpose/document/version; GIVEN не принимает supersedes. Действующий GIVEN требует текущую версию документа, живой anchor, отсутствие последующего revoke. Устаревший текст не принимается молча. Отзыв старой принятой версии допустим после смены текста, при живом anchor. Все действия сериализуются lock session → document; после ожидания document lock срок anchor проверяется заново, а время принятия события задаётся DB clock. Повторное GIVEN новой версии не требует искусственного отзыва старой; REVOKED относится только к указанному GIVEN и не гасит более позднее самостоятельное согласие. Evidence не содержит raw PII/token. Idempotency через evidence_ref unique(session_id,evidence_ref): повтор проверяет live anchor/ownership и совпадение payload; replay старого GIVEN не восстанавливает отзыв и не принимает stale text. Anchor передаётся как trusted server identity/proof, браузерный UUID сам не авторизует.

## Внутренние порты и транзакции

Приложение предоставляет функции на `PoolClient` внутри явной транзакции caller; нет DI/HTTP регистрации и raw browser inputs. Для legal-операций caller открывает её через `beginLegalTransaction(client)` — `BEGIN ISOLATION LEVEL READ COMMITTED`, до первого чтения/изменения данных. Guard legal-порта сначала выполняет `SET TRANSACTION ISOLATION LEVEL READ COMMITTED`, затем проверяет фактический `transaction_isolation` и наличие явной транзакции. `REPEATABLE READ`/`SERIALIZABLE` с уже полученным snapshot отклоняется (SQLSTATE 25001 → типизированный `CONFLICT`), не превращается в `GRANTED` и не перезапускается автоматически; caller делает ROLLBACK и начинает новую RC-транзакцию. PostgreSQL/ORM defaults не являются контрактом. Runtime получает только используемые column-level SELECT/INSERT/UPDATE; нет DELETE/TRUNCATE/DDL, PUBLIC доступа или SECURITY DEFINER делегирования. Любой внутренний publish/archive/consent write добавляет безопасные audit+outbox в той же транзакции (идентификаторы/цель/версия, без body/legal text/PII/secrets). Сбой audit/outbox откатывает операцию вместе с caller transaction. Аутентификация/capability policy остаётся внешним обязательным портом P03-05/P05; эти функции не объявляются защищёнными endpoints.

### Адресная доработка по независимому ревью (21.11.2026)

1. **Текущая актуальность согласия:** legal-порты устанавливают и проверяют READ COMMITTED до собственного data access. Официальный вход — `beginLegalTransaction` до первого чтения/изменения. Уже полученный RR/Serializable snapshot не используется для решения и не переводится молча на новую транзакцию: типизированный отказ `CONFLICT`, затем caller ROLLBACK. Общий guard защищает `currentPurposeConsent`, запись/повтор GIVEN, REVOKED и trusted-proof путь. Исторические DTO/`anchorState` сами по себе не являются разрешением по согласию.
2. **Timezone provenance:** DTO `ReferenceResolution.timezoneCityVersionId` — exact ID строки города, давшей timezone; `versionId` — отдельная ревизия справочника, creation provenance не меняется. CITY проверяется same-city, COMPANY возвращает оба timezone-поля NULL.
3. **Expiry во время ожидания:** `recordConsentRevoked` перепроверяет DB clock после `FOR UPDATE` документа и до проверки отзыва/INSERT; истечение возвращает `SESSION_EXPIRED`. Отказ не добавляет consent/audit/outbox, исходный GIVEN остаётся неизменным. Schema trigger уже имел финальную expiry-проверку, но она не заменяет точный application error.

### Что этот срез не обещает

- Company/reference/content publish — CAS-операции без transport idempotency receipts. После потери ответа caller перечитывает версию; HTTP-слой с авторизацией, replay и квитанциями — P03-05.
- `reviewed_by` company-ревизии означает издателя этой ревизии, не повторную юридическую экспертизу каждого перенесённого поля. Само основание переноса сохраняется в policy refs и предыдущих immutable ревизиях; смена primary переносит все семь полей.
- У архивированных reference/content нельзя очистить или изменить `archived_at`, назначить новую версию либо создать новую ревизию; старые снимки доступны отдельно от выбора для нового использования.
- Legal locking reads/consumption требуют явную read-write READ COMMITTED транзакцию на primary, открытую до первого data access через `beginLegalTransaction`; не replica и не autocommit. Внутренний `listSessionConsent` по-прежнему требует правильное доказательство владения anchor и может прочитать его минимальную evidence-историю после expiry/revoke; это не право на запись/доступ к файлам/заявке и не публичный маршрут. Post-submit history и связь к заявке добавляются в P05 без переписывания evidence.
- Типизированные policy refs не исполняют retention/upload/security политику. Scanner, файлы, очистка, реальные юридические решения и production остаются вне этого подэтапа.
- Механическая `settingsReady` включена в auth-enabled readiness, как и защищённый staff-контур. При выключенной auth технический foundation может быть healthy без 013; это не объявляет готовыми настройки/intake, а новые внутренние порты не становятся публичными.
- Создание stable legal-document identity пока не принимает staff actor: это внутренний structural порт без защищённого HTTP. Publication audit содержит reviewedBy; session/consent audit содержит точный anchor/evidence. P03-05 обязан добавить проверенный staff actor и capability к административной команде создания документа, а P05 — доверенный выпуск F-сессии и правила её использования.
