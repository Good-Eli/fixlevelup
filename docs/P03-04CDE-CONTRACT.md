### Ordering and compatibility (shared A/B/C/D code)

- First acquire runtime singleton `FOR SHARE`, if present, before session/document/intent; check expected namespace and epoch for C/D/restore. Shared mode permits all ordinary tx in parallel; exclusive lock only short epoch transition, never storage/worker calls. Then `request_session → legal_document → owned intent → privacy control → attempts/publication/delete items` sorted by stable IDs for multiple rows. Technical path uses exact stored owner/doc, not raw F proof; use same lock order. C/D never perform DB work on stale RR, network waits with checked-out client, or assume wall clock is DB clock. Time recheck after last selected row/lock/audit wait, before receipt/admission or mutation.
- A read and exact reservation replay take runtime `FOR SHARE` before session/document and privacy control `FOR UPDATE` after the owned intent, before any DTO/replay. D freeze or non-ACTIVE runtime gives `CONFLICT`. The existing five-key cancel receipt is unchanged.
- New B/C write commands and their replays require the authoritative `ACTIVE` epoch `1n` before any source/body/raw GET/worker/sanitized PUT or command receipt. Missing singleton preserves legacy B on the full schema in non-restored databases; C requires an explicit matching epoch. Restored `ACTIVE` epoch 2+ rejects B/C write commands with `NOT_CONFIGURED`; an initially configured active epoch >1 also denies new writes. This is a deliberate technical synthetic profile matching the original-target delete broker's epoch-1 authority, not a business default. A valid new no-byte intent in restored ACTIVE does not authorize byte IO. Technical cleanup/reconcile may still record factual observations under trusted authority; it cannot re-enable writes.
- B probe candidate selection excludes D-frozen intents and checks exact target and the shared owner live budget (raw/sanitized attempts, B probe debt, read/processing claims) **before `LIMIT`**, then rechecks under locks. Shared owner SQL in `upload-coordinator/accounting.ts` avoids divergent capacity rules. Expired leases or absence observations never auto-free unsettled debt.
- Reuse existing F consent/authorization path (extract private shared helper rather than an alternate policy path). Owner by raw F proof, exact bound old GIVEN/version/purpose, current doc and non-revoked live DB session, RESERVED/non-expired original intent+policy, MIME present in original allowlist. Quota recalculation applies for write/process as B; metadata/stream not blocked by unrelated owner's new reservation quota. Existing B receipt rechecks clock after exact binding SELECT. No part accepts caller target/owner/basis/byte count/time as authority. Lock release before private object calls.
- Raw and sanitized registration share per-owner `maxAttemptsPerOwner`, `maxPhysicalBytesPerOwner`, `maxLiveOperationsPerOwner` in `UploadOperationalPolicy`, aggregated under same owner lock: both attempt tables, all targets; charge all rows minus FAILED_NOBYTES; live REGISTERED/IN_FLIGHT/UNKNOWN plus B probe debts and active processing/read claims (charge command exactly once if a claimed phase already counted as a write workflow; don't age out unproven network debt). No lifetime reset/new numerical defaults. Check both before new side effects and after waits at commit checkpoints. Access uses separate bounded pool of reader jobs/RAM; don't allow retries to overrun resources while an old holder hasn't settled. Every stage increments audit/outbox or explicitly documents no transition.

Use fixed pinned binary `clamscan -` and [fail-closed limits](<P03-04CDE-PROPOSAL.md#L20-L29>); accept CLEAN only after full stdin success and confirmed process exit, both bounded stdout/stderr EOF, exactly one known clean response and zero unrecognized warnings/late diagnostics/skips/limits. - Read: `readReadyMetadata` same auth+fresh clock after exact publication read, including epoch/absence of freeze and `now < least(publication.published_at + maxAccessAgeMs, access policy expiry, intent, session, original policy expiry)`; never expose a non-ready DTO. `openReadyStream` same auth then one per-intent reserved read generation/lease **and global trusted stream-slot+RAM reservation before GET**, shared across all contexts/publications of the configured runtime, counting opening and live tickets (budget includes full staging bytes, peak copies and output chunk); for synthetic this is one trusted process, no per-call limiter or multi-process assumption. No prefetch/parallel pulls; ambiguous COMMIT/revoke/close/expiry aborts further chunks, expired old ticket never resumes regardless of later new claim. Release claim by exact generation/ID, global RAM slot only after closing and **actual** pending GET/pull settles and private bytes discarded; no lease-based remote debt reset. Locks/connection released before consumer code. Consumer waits backpressure; at revoke one already admitted chunk may finish, none newly admitted. Q12 window is injected synthetic only.
