## 1. Публикация, схема и SQL-границы

Везде `foundation`, UUID id, целочисленная sequence/CAS, restrictive FK, SQL constraints и минимальные runtime ACL. Ссылки на `service_city_versions(city_id,id)`; новая версия привязана к текущей опубликованной версии своего города (не переключаем lifecycle), существующие ссылки immutable. Реальный доступ не выдаётся. Точный контракт столбцов (дискриминаторы/связи помимо перечисленного согласовать root):

- `price_rules(id,code,kind,row_version,archived_at)` — company-wide identity; canonical slug, уникальный code; kind `EVENING/NIGHT/EXPRESS/SURCHARGE/DISCOUNT` immutable; terminal archive запрещает version publish/новое использование, истории не мешает. Приоритет не зависит от ID/enum/порядка запроса.
- `price_rule_series(id,city_id,rule_id,row_version)` unique `(city_id,rule_id)`; `price_rule_versions` — общие version fields ниже, `rule_id,kind` (точные same-rule refs), `title` 1..160, `method` FIXED/RATE, `base` WORKS/WORKS_AND_PARTS/ORDER_BASE, required `currency` `[A-Z]{3}` for both methods (cannot reinterpret an old delta under a new currency), `fixed_minor` или `rate_bps`, `min_base,max_base,min_delta,max_delta`, `start_minute,end_minute,wraps_midnight`, `scope_count`. `fixed_minor` ∈ BIGINT magnitude, `rate_bps` 1..10000, один из двух. Bounds nullable и min≤max. Temporal window only EVENING/NIGHT; минутные 0..1439, unequal, wrap iff start>end; все три поля NULL во всех других видах. `price_rule_scopes(rule_version_id,category_id,category_kind DEFAULT 'CATEGORY')`: unique pair, real typed category FK; `scope_count` 0..32, exact child count via deferred guard on both owner and child INSERT, no update/delete/truncate. Empty scopes = unrestricted; if some, apply only to explicit category matches.
- `pricing_policy_series(id,city_id,row_version)` unique city. `pricing_policy_versions` — общие поля + `currency` `[A-Z]{3}`, `tax_display` nonblank ≤200 (вывод, не налогообложение), `rounding_mode` HALF_UP/DOWN, `units` JSONB object `{[unitSlug]:scaleInt0…6}` of 1..32 entries strict through immutable SQL validator (без defaults), `max_manual_delta_minor` nonnegative BIGINT (лимит одной ручной корректировки), `priority_count` 0..64, `compatibility_count` 0..128. `price_rule_priorities(policy_version_id,rule_id,priority)` unique pair, FK to policy/definition, priority bounded integer 0..1000000 (higher wins). `price_rule_compatibilities(policy_version_id,left_rule_id,right_rule_id)` unique triplet, FK to policy/definitions, sorted `left < right` by UUID (unordered pair), deny by default. Exact child counts held by deferred parent+child triggers; no mutating/detaching a published policy. Directions/compatibility run only among candidates read for this city, not inherited from others. A policy may reference stable definitions of future scheduled versions; in calculation must supply priority for every eligible automatic rule, including a sole candidate. Pairwise permission required for every applied pair including manual rules; no implicit exceptions or surprises.
- `public_price_estimate_series(id,city_id,category_id,category_kind DEFAULT 'CATEGORY',code,row_version,archived_at)` unique `(city_id,category_id,code)`, immutable typed category; terminal archive supports internal lifecycle. `public_price_estimates` — common version fields + `title` ≤160, `currency`, `min_minor`, `max_minor` nonnegative BIGINT and min≤max, `conditions` (nullable ≤1000), `disclaimer` (required ≤500); no FK to fixed prices, no money-reading fallback, no public publication. `source_ref` required and review provenance retained. Zero endpoint is an estimate bound, not a fixed free price.
- Common version fields: `id,series_id,city_id,city_version_id,version,source_ref,reviewed_by,published_at,valid_from,valid_until`. Append-only. One exact projection each `price_rule_periods`, `pricing_policy_periods`, `public_price_estimate_periods`: same `version_id PRIMARY KEY,series_id,city_id,valid_from,scheduled_until,closed_effective_until`; composite FK to version `(id,series_id,city_id)`, reverse deferred FK requiring projection. INSERT verifies projection matches all original bounds, no initial closure; guard exact UTC milliseconds finite, start strictly future vs floored DB clock, terminal close allowed once only for currently effective interval with `T>now` and `T<scheduled_until` if set. EXCLUDE `(city_id,series_id,tstzrange(...,'[)'))` reuses existing GiST extension in `foundation`; each natural key unique in its series, hence no same-city ambiguity. SQL deferred final-check rejects crossing T during waits before commit processing (trusted SQL callers do not force immediate constraints). A future predecessor that is not effective cannot be prematurely closed; no rewrite of source title/amount/date/reviewer. KEEP SHA `019` unchanged.
- All allowed catalog/pricing direct INSERT/UPDATE `BEFORE STATEMENT` use `foundation.catalog_lock_write()` same exclusive xact lock `(77304,1)` and READ COMMITTED; no reverse acquisition after city or resource row. Application fences before reads then locks referenced city `FOR SHARE`, validates typed active refs, CAS with expected 0 on first city stream or 1+ thereafter, inserts version/children/projection. `replace` closes old projection and inserts replacement at exactly T in the same tx and bumps CAS once; `close` advances CAS once. New series for rules/policy created only upon publish in the application; public estimate identity may be created without published version; `archive` CAS increments and hides new effective listings, no history destroyed. After unknown COMMIT reconcile exact target/value/version; no automatic retry, same stale expected version can't apply twice; authenticated HTTP receipts later. Every application mutation emits one safe audit/outbox pair in the **same caller transaction**, savepoint rollback if caller catches, no raw text/URL/money in logs. SQL direct DML is a trusted runtime credential boundary, not app actor auth.

## 2. Engine / repository interface

`apps/api/src/pricing/engine/` owns TS types/config validation/pure arithmetic. Export `PricingInput`,`PricingResult`,`calculatePricing(input:unknown)`, `PricingError` with code (`INVALID_INPUT`, `PRICING_NOT_CONFIGURED`, `PRICE_NOT_CONFIGURED`, `PRICING_CONFIGURATION_AMBIGUOUS`, `ADJUSTMENT_NOT_AUTHORIZED`, `OVERFLOW`, `NEGATIVE_TOTAL`). Return `{ input: PricingInput, lines, breakdown, totalMinor }` with deeply immutable canonical-normalized copied `input` and canonical order, trace sufficient to recompute. Engine accepts only an internal resolved trusted data contract, never body/user supply of prices or evidence. Fields below are exact, string dates ISO millisecond UTC except named wall representation. Config/time/amount parsers fail closed on fields/ranges. No floating-point monetary arithmetic, DB bigint casts to text before JSON. Stable sorting is only for serialization.

- `context:{calculationId,cityId,cityVersionId,timezone,pricingAt,tariffAt,localAt,utcOffsetSeconds,express}` with UUIDs, zone (IANA `UTC` or named Area/Id), `localAt` as ISO wall clock `YYYY-MM-DDTHH:mm:ss.sss` without offset; signed integer offset seconds, bounded |offset|≤18h; verify localAt = UTC tariffAt+offset exactly without consulting tzdata in engine/replay. PostgreSQL resolves `localAt`+offset from city version (`AT TIME ZONE`), never browser. Current pricing caller supplies trusted `tariffAt`, not `pricingAt`; chosen by logic outside P04 under separate Q10. Only one evaluation of both date/time values for all rules.
- `policy:{id,cityId,cityVersionId,currency,taxDisplay,roundingMode,units,maxManualDeltaMinor,priorities:[{ruleId,priority}],compatibilities:[{leftRuleId,rightRuleId}],validFrom,effectiveUntil}`; exact IDs, effective boundary includes `pricingAt`; copied immutable defaults none. SQL 020 materials supply policy (null→`PRICING_NOT_CONFIGURED`; >1→ambiguity); effective policy stable per city, no fallback. Rules with missing configuration never silently masquerade as configured: no active version for an unconfigured definition is not a candidate; a matching version with bad shape/refs causes refusal.
- `items:[{lineId,itemId,itemVersionId,kind,categoryId,unit,title,quantity,price:{id,cityId,cityVersionId,itemId,itemVersionId,amountMinor,currency,zeroBasis,validFrom,effectiveUntil}}]`. Nonempty ≤128, lineId UUID unique; categoryId nullable except WORK, unit exact immutable SKU unit (selection supplies requested unit, adapter checks against SKU), price reviewed `itemVersionId` distinct from top-level current revision when relabelled. Price and metadata source IDs, amount, timestamps sealed. Same city on both price and rule; old reviewed city version may be older (adapter FK proves it belongs to same city, not necessarily current). Current eligibility/flags checked from single statement. `MATERIAL` belongs to WORKS, `PART` to PARTS. Seal quantities and explicit no-charge basis; a missing current fixed price is not range/fallback.
- `rules:[{ruleId,id,cityId,cityVersionId,kind,title,method,base,currency,fixedMinor,rateBps,minBase,maxBase,minDelta,maxDelta,startMinute,endMinute,wrapsMidnight,categoryIds,validFrom,effectiveUntil}]` (nullable exact fields), active ≤64, duplicate definition/revision is ambiguity; input validation all candidates before any filtering; category IDs distinct sorted. Automatic EVENING/NIGHT/EXPRESS, manual SURCHARGE/DISCOUNT only selected by approved adjustment and never auto. Evaluate time/day boundary in saved local minutes, midnight wrap exact, applicability express explicit. Base = canonical sum of allowed rounded item amounts; empty category/base sets don't activate even a fixed rule. Base bounds inclusive; nonmatching auto candidate skipped, explicitly selected adjustment failing eligibility refuses. Compute `HALF_UP/DOWN`, apply delta floor/cap then sign, no rounding total. Above-plan limits/stack checks from §4; compatibility requires explicit pair; repeated use of the same manual rule in one calculation forbidden (cannot split amounts to evade per-adjustment cap). Trace line fields must include line component, ordinal stable key, magnitudes (string), source IDs in frozen `input`, base/raw numerator/denominator/rounded/capped where applicable. Checked BIGINT on base/line/component/total stored, intermediate products unbounded BigInt over bounded inputs. Currency codes must match policy.
- `adjustments:[{id,ruleId,reason}]`, `evidence:[{id,calculationId,adjustmentId,cityId,policyVersionId,ruleVersionId,currency,baseMinor,appliedMinor,decision,actorId,reason}]`, ≤32 each and exactly one matching trusted record per applied manual adjustment, no unused records; all identity references, reason, amount/base after rounding/caps are compared literally; duplicate evidence ID, duplicate adjustment ID or duplicate manual rule fails. Evidence is already verified by trusted producer (only synthetic fixtures today), `decision` WITHIN_LIMIT iff amount <= policy cap, OVER_LIMIT_APPROVED iff > cap, explicit actor/reason always required. No raw client transport or self-approval. A quote approval ledger/same decision consumption across calculations belongs to P11; no effect of applying/persisting a charge in P04. Internal preview on invalid evidence must not return a partial money result (replay uses already sealed trusted provenance).
- `breakdown:{travel,diagnostics,works,parts,timeSurcharge,expressSurcharge,approvedSurcharges,approvedDiscounts}` integer minor strings; each line one component; `totalMinor` plus trace. Persisted/canonical input distinguishes implicit data from claims: recorded output is deterministic for exact sealed input, not authority for a new decision.

`apps/api/src/pricing/repository/` implements mutations with separate type input as above and narrow methods: `createRule`, `archiveRule`; `publishRule`, `closeRule`, `replaceRule` scoped by city/rule; `publishPolicy`, `closePolicy`, `replacePolicy`; `createEstimate`, `archiveEstimate`, `publishEstimate`, `closeEstimate`, `replaceEstimate`. Writes `(client,reviewedBy,input)` return `{id,version}` optionally revision fields; prefer fault-specific `CatalogError`/`CatalogInternalError` mapped across existing savepoint and safe errors. For estimate publish target existing `estimateId` and same city; pending over-limit support by concrete evidence in engine, no approval API. `readEffectiveEstimates(client,{cityId,cityVersionId,categoryId})` returns bounded reviewed records of current city + time (no side effects and not public) with range amounts not fixed. `readPricingInput(client, {calculationId,cityId,cityVersionId,tariffAt,express,selections:[{lineId,itemId,unit,quantity}],adjustments,evidence,visibility?})` is a trusted server-side boundary (no `pricingAt`, prices or raw rules supplied; optional visibility exactly TECHNICIAN/PUBLIC, otherwise internal read). It gets READ COMMITTED shared fence in separate first statement (reuse marker/probe), then a single statement timestamp, one snapshot policy/rules/line source/city, parameterized selection list (lineId,itemId,unit,quantity) and trusted tariff/express/evidence validated finally by engine. Missing/duplicate sources, city pointer or visibility mismatch, bounds exceeded deny entire read. No sequential calls to P04-01 reader to assemble calculation. Use stable indexes and read at most `cap+1`. No HTTP. Snapshot/load adapter assembled at root, no new runtime dependency.

`apps/api/src/pricing/codec/` owns duplicate-aware bounded strict JSON, canonical serialization + digest/replay. `sealPricing(input)` calls trusted engine, returns `{bytes:string,sha256:string}` with canonical `{version:1,input,lines,breakdown,totalMinor}`; `verifyPricingSnapshot(bytes,expectedSha256)` expects caller-trusted digest, validates bounded strict text including UTF-8, unknown fields, duplicate decoded keys per object, canonical scalar/string order/representation and all replay output equals bytes after recomputing from input, does not consult DB/timezone/tzdata. JSON reader is reusable in P04-03 (separate export, no receipt-scope effects): strict numeric tokens integers in safe numerical range, no exponent/fraction/sign ambiguity, strings carry fractions or BIGINT; parse rejects negative zero; bounded depth/nodes/bytes, no getters/proto pollution, catches malformed input safely. Do not use unsafely parsed last-field-wins JSON. SHA‑256 equality is integrity only, verified adjustment authority remains an out-of-band trusted input; old persisted records remain valid with old digest after prices/clock/local context change. Codec proof duplicate escaped keys, very large numeric token, canonical order, unexpected key, mutated digest/altered recomputed result, old wall offset.
