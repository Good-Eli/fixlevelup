## 1. Как устроена работа

- [Закрытая CRM](../apps/web/app/crm/access/desk.tsx) остаётся на `/crm/access`. [Разделы P04](../apps/web/app/crm/access/p04/workspace.tsx) открываются только по соответствующим разрешениям. Каталог компании, определения тарифов и Авито требуют свои точные GLOBAL grants у SYSTEM ADMIN. Цена, тарифная версия, политика и диапазон управляются только в выбранном городе, с обоими `pricing.read` и `pricing.manage` и, при CITY scope, действующим назначением. Нельзя вывести grant из имени роли, P03-прав или наличия записи в справочнике. `cityList` не подставляет первый город. `/access` возвращает [ограниченную проекцию](../apps/api/src/authz/authorization.service.ts#L341-L358) только собственных активных CITY assignments при scoped pricing; это подсказка для управления, не авторизация. При `pricing.read GLOBAL` / `pricing.manage CITY` один только список для чтения не открывает write controls. [Реальная PG-регрессия](../apps/api/tests/p0404-access.test.ts) проверяет отсутствие проекции без grants, изоляцию / отзыв и итоговый отказ записи.
- [Клиент](../apps/web/app/crm/access/p04/client.ts) использует сгенерированный контракт P04. Только относительный канонический путь, `credentials`/`mode: same-origin`, `cache: no-store`, `redirect: error`, лимит UTF-8 и запрет неверной проекции/ETag/версии. Суммы остаются точными ASCII-строками, включая `9223372036854775807`; диапазон никогда не становится фиксированной ценой, пустая цена не ноль. [Городские формы](../apps/web/app/crm/access/p04/city-forms.tsx) требуют явные UTC-миллисекунды, базу/метод, локальное окно для EVENING/NIGHT, ограниченные строки точности/приоритетов/совместимости, без JSON-редактора или подставленных бизнес-значений. Publish использует версию текущего ряда, Close/Replace дополнительно требуют подтверждённую точную ревизию и её неизменную привязку к городу; архивные данные доступны только по своей истории. Для известного ID архивной позиции/правила есть read-only вход в историю выбранного города: сервер снова авторизует весь target, этот вход не показывает формы записи.
- [Общее управление](../apps/web/app/crm/access/desk.tsx) проверяет staff ID/CSRF/auth generation и свежий P04 access до и после чтения, до записи и явного повтора. Только одна команда в полёте; logout/unmount отбрасывают ответ. Подтверждённый отказ обновляет доступ и сбрасывает старые карточки. [Черновик](../apps/web/app/crm/access/p04/shared.tsx) хранится в памяти только для той же сессии и формы точной цели, восстанавливается явно после повторного чтения, без прежней V/ключа и без добавления недоступных вариантов выбора. Сбой/непроверяемый результат после отправки закрывает редакторы; «Проверить / повторить» отправляет тот же URL, JSON, I и V только после новой проверки живой сессии/доступа. Никакого автоповтора, storage или показа тела серверной ошибки. [Тесты transport](../apps/web/tests/p0404-client.test.ts) подтверждают точный replay, scoped hints, капы, binding и отказ при смене сессии.

## 3. Проверяемый запуск и ограничения

Из корня проекта — [изоляция и команды браузерного запуска](../infra/p0404-browser-smoke/README.md). Войдите тестовым CITY-менеджером в новом контексте, откройте городские цены, явно выберите доступный город и позицию, загрузите историю и задайте будущую дату. Не подставляйте незаданные цену/скидку. После публикации перечитайте историю и проверьте точную сумму и ревизию. Для P03 переходов из каталога создайте район/зону, измените и опубликуйте покрытие; создайте новый контакт как city version и опубликуйте FAQ через «Контент». Никакого ручного прогона на рабочей БД или реальной учётке. Цены/лимиты, значения Q06/Q09/Q10/Q15, полномочия сотрудников, реальное согласие на Авито и production остаются за отдельными gates. ### Первый аудит и исправления

Первый аудит GPT‑6.2 Astra (`high`) дал **FAIL** редакции с 1048/1048 Vitest и 204/204 Playwright: черновик создания мог пережить смену неизменяемого родителя; восстановленный набор категорий мог потерять недоступную категорию; квитанция Close/Replace могла указать другой ценовой ряд. [Три RED](../node_modules/.cache/p0404/browser-audit-red.log#L5-L87) воспроизвели все три контрпримера на исходном production-образе.

- [COMPANY-формы](../apps/web/app/crm/access/p04/company.tsx) включают в ключ черновика вид и все выбранные неизменяемые parent IDs, включая точное отсутствие необязательной категории. При смене цели сбрасывается и сама форма, не только кнопка восстановления.
- [Восстановление](../apps/web/app/crm/access/p04/shared.tsx#L29-L118) сначала сверяет весь набор значений с текущими вариантами. При недоступном выборе поля не подставляются, отправка заблокирована; можно загрузить недостающую страницу или отдельно подтвердить отказ от черновика. Перед отправкой сверяется исходный набор выбранных вариантов. Ни восстановление, ни отказ от него не отправляют команду.
- [Городской редактор](../apps/web/app/crm/access/p04/city.tsx) связывает Close/Replace с проверенной точной версией и её `seriesId`, а повторный Publish — с рядом из текущей истории. [Клиент](../apps/web/app/crm/access/p04/client.ts) фиксирует ожидаемый ID локально; он не попадает в URL, тело или заголовки. Квитанция другого ряда считается неподтверждённой даже при верных `V+1` и ETag; явный повтор сохраняет все исходные байты и проверку ожидаемого ряда. Для первого Publish без ряда допустим только `V=0` из проверенной пустой истории.
