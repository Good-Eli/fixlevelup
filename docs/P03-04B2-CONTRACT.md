Historical implementation contract for accepted B2 (22.11.2026), with the later integration delta below. Implements the approved [B proposal](<P03-04B-PROPOSAL.md>) over the [B1 storage boundary](<P03-04B-STORAGE.md>) and immutable [A reservation](<P03-04-CONTRACT.md>). Synthetic F-owned flow only. ## Interfaces shared by implementation and tests

`apps/api/src/files/upload-coordinator/index.ts` (internal feature entry point; no controller):

```ts
uploadReservedFile(pool: Pool, storage: RegisteredQuarantineStorage,
  operationalPolicy: UploadOperationalPolicy, command: UploadReservedFileCommand): Promise<UploadQuarantineReceipt>;

// Parts of UploadReservedFileCommand (all mandatory):
// session: FileOwnerSessionProof; intentId: UUID; idempotencyKey: UUID;
// body: (signal: AbortSignal) => AsyncIterable<Uint8Array>; signal: AbortSignal;
// UploadQuarantineReceipt: { intentId, quarantineId, state: 'QUARANTINED', replayed: boolean }
```

- `body` is an internal cooperative producer factory, not JSON or a URL: uses the provided native signal to stop pulling/settle `next()` and release its own resources. Pass it the coordinator's linked deadline/abort signal, never a token. No factory/iterator getter/call/`next()` before confirmed registration COMMIT. Synchronous CPU-blocking or non-cooperative arbitrary JS cannot be forcibly cancelled; do not wire untrusted in-process producers.
- Trusted `UploadOperationalPolicy` is a closed, runtime-validated snapshot, **not** part of the command: `{ mode: 'local-synthetic', maxAttemptsPerOwner, maxPhysicalBytesPerOwner, maxLiveOperationsPerOwner, leaseMs, prefixTimeoutMs, maxSourceChunkBytes, allowedMimeTypes }`. All numeric fields explicit positive bounded integers; bigint-safe physical cap, attempt/slot caps fit PG `integer`, timeouts fit existing B1 technical ceiling, `prefixTimeoutMs < leaseMs`, nonempty distinct supported MIME subset. `maxSourceChunkBytes` must not exceed adapter chunk cap. Validate and copy primitives/allowlist before awaits. No policy or malformed policy → `NOT_CONFIGURED`, no IO. No defaults or approved live values.
- Require exact raw A `FileOwnerSessionProof` (only `sessionId` and `token`); snapshot plain own data fields, validate UUIDs/token/native signal; convert caller reflection/access/producer failures to fresh fixed errors without `cause`, diagnostics or echoed values. Raw proof lives only in this command's memory, never in a DB row/job/outbox/queue. Server generates descriptors, lease IDs and binding IDs. No caller-supplied key, target, clock, declared byte count, MIME, consent ID, or checksum.
- `UploadCoordinatorError` exposes fixed codes only: A proof/consent/intent/configuration refusals as applicable, plus `IDEMPOTENCY_CONFLICT`, `ATTEMPT_ACTIVE`, `ATTEMPT_FAILED`, `WRITE_OUTCOME_UNKNOWN`, `ALREADY_QUARANTINED`, `ATTEMPT_BUDGET_EXCEEDED`, `PHYSICAL_BUDGET_EXCEEDED`, `LIVE_OPERATION_LIMIT`, `SIGNATURE_MISMATCH`, `SOURCE_FAILED`, `ABORTED`, `STALE_ATTEMPT`, `CONFLICT`. Wrong proof/foreign or missing intent → `NOT_FOUND`; no failed-auth metadata. No public GET metadata operation. Only the four receipt fields above; no hashes, object identifiers, URI, secrets, or raw error values.
- `upload-coordinator/reconcile.ts` is an operator-only direct invocation, not the command barrel: `reconcileUploadAttempts(pool, storage, operationalPolicy, { limit, signal }): Promise<UploadReconcileSummary>` with bounded positive `limit` (technical cap ≤100), returning aggregate enum/count data only. No externally selected intent/attempt/key, no new worker infrastructure. Private transaction helpers (`registerUploadAttempt`, `authorizeUploadDispatch`, `finalizeUploadAttempt`, `recordAttemptOutcome`, probe claim/finish) take the existing transaction's client; no helper commits, performs storage IO, or accepts an unauthenticated browser UUID as authority.

## Transaction and IO protocol

1. Own primary `Pool` transactions: `beginLegalTransaction` then `assertCallerTransaction` before data access; commit/rollback/release on every exit, discard a client with ambiguous commit/connection outcome. **No transaction or checked-out client waits on source or S3.** Authorization lock order `session → document → owned intent → attempt`, deterministic order if locking multiple attempts. `requireLiveAnchor` + `currentPurposeConsent({session,purpose:'REQUEST_PROCESSING'})` lock/prove the first two; then `FOR UPDATE` owned intent and relevant attempts. A/Cancellation locks a compatible subset. After last waiting lock, recheck with fresh PostgreSQL `clock_timestamp()` (exact timestamp comparisons in SQL, not app `Date.now()`): session live, current document + exact GIVEN id/version/purpose of intent, `RESERVED`, live policy and intent, unchanged intent row version, and lease/generation when relevant. Locks stabilize consent/policy/state evidence; never substitute a different/new GIVEN. Check the intent MIME against both snapshots and the file size against 014. Recheck A owner logical count/bytes of live `RESERVED` against this intent's snapshot, **no +1 for this intent** (already counted).
2. Under session lock, first re-read by `(owner,idempotencyKey)`: conflict if for another intent; if its exact binding exists, re-authorize and return it with `replayed:true`; otherwise return fixed active/failed/unknown error for the prior command, never use its body or old descriptor. Different key on already bound intent → `ALREADY_QUARANTINED`. New accepted command generates a B1 descriptor once and DB generation `max(intent generation)+1`. Live active attempt → `ATTEMPT_ACTIVE`. Retire expired active attempts under lock: `REGISTERED → FAILED_NOBYTES` is safe because no durable dispatch and the old CAS can no longer pass; `IN_FLIGHT → UNKNOWN` never releases possible written bytes. Evaluate budgets below while holding session lock; new attempt starts `REGISTERED` with fresh random lease ID and expiry ≤ DB now + configured leaseMs, clipped to intent/policy/session expiry.
3. INSERT registration + audit/outbox then **COMMIT** before producer creation or first `next()`. If registration COMMIT outcome ambiguous, on a fresh primary client re-lock/re-authorize and verify the exact winning attempt, key, target, intent/owner, idempotency key, generation, same lease ID/expiry and state `REGISTERED`. Only the original in-process invocation with that exact descriptor/grant may proceed; otherwise no IO. No automatic replacement insert or old-key replay. Registration rollback leaves no byte IO. A duplicate command, even with same idempotency key, is never this originating invocation.
4. Outside DB, inspect a small copied prefix, then replay exactly that prefix and the copied remaining part of the crossing chunk into B1 (no skipped/duplicated bytes). Offset 0 signatures: JPEG `FF D8 FF`; PNG `89 50 4E 47 0D 0A 1A 0A`; WebP `RIFF` at 0 and `WEBP` at 8 (12 bytes minimum); PDF ASCII `%PDF-` at 0. Disallow truncated prefix, mismatch and absent validator; no filename/MIME inference, no scanning/decoding claims. Keep ≤12 prefix bytes plus at most one capped chunk/remainder; validate chunk type/length before copying, enforce actual total size, finite deadline and periodic event-loop yield even on zero-byte chunks. No full buffering. Native combined abort + bounded prefix deadline, guarded iterator cleanup (`return` getter/call once, no unhandled rejections), no further pull after stop. Pre-dispatch failures can retire `REGISTERED` as `FAILED_NOBYTES`; **no PUT**. Do not classify a B1 error after dispatch as no-write.
5. New RC transaction: re-authorize and CAS exact current attempt/lease to `IN_FLIGHT` under the normal locks, checking time again; COMMIT the one-way dispatch permit before calling `putQuarantined` once. Ambiguous dispatch COMMIT: fail closed, no PUT (treat an `IN_FLIGHT` row as possible write for accounting); never adopt an existing dispatch marker. Check linked signal/deadline immediately before call. Lease bounds app initiation and DB use, **not** remote PUT visibility; network can finish late. B1's `maxAttempts=1`/one-shot descriptor + new random key per new DB generation remain mandatory. PUT with 014 expected bytes and the reserved charge as cap; verify via independent bounded GET on the *same live descriptor and same target*, comparing PUT receipt id/key/size/hash and GET receipt. No HEAD/ETag. Do not pass GET content outside storage.
6. New RC transaction: re-prove full authorization, exact current generation/lease, no cancellation and logical/physical/live bounds (count current attempt once). On matching successful storage facts only, write technical `VERIFIED` + sole immutable binding + audit/outbox **atomically**. Success only after COMMIT. Ambiguous final COMMIT: fresh fully authorized exact command replay of an existing binding only, never PUT again. A cancelled/revoked/stale/expired command yields no binding or receipt, even if the bytes arrived. No attempt to compensate by DELETE or mutate A. Deadline/signal prevents new initiation/publication; cleanup may still write technical facts on an independent trusted tx.
7. On post-dispatch failures/denials with no successful binding, a separate private `recordAttemptOutcome` may record `UNKNOWN`, or `VERIFIED` unbound **only** with matched full original PUT+GET facts and still-current, live lease; compare attempt ID/target/generation/lease from the captured internal grant, never from the browser. No raw proof needed or persisted on this technical path. Stale/expired holder cannot write winning state or authorize; leave unresolved for probe. Technical operations can lock retired rows even when user authorization is dead; use trusted DB lookup of exact owner/document IDs and same forward lock order (no `requireLiveAnchor` gating technical accounting). Rollback or unavailable DB leaves durable earlier marker, charged conservatively; no unsafe status synthesis.

## Accounting in accepted B2 (per immutable 014 owner, all targets/intents)

- `maxAttemptsPerOwner`: all committed attempt rows, lifetime for this owner including FAILED/CANCELLED/expired/verified; reserve +1 only for a new attempt. This deliberately fails closed at exhaustion; B2 provides no reset/delete mechanism.
- `maxPhysicalBytesPerOwner`: sum `charged_bytes` for every row except `FAILED_NOBYTES`; includes both bound and unbound verified rows, active reservations and UNKNOWN/orphans regardless of intent/session/lease expiry or cancellation, regardless of 404 or smaller observed bytes. New attempt adds its own expected size once; bigint arithmetic (e.g. SQL numeric/text+BigInt). No second charge on binding. A's logical expiry is irrelevant to this sum.
- `maxLiveOperationsPerOwner`: count `REGISTERED/IN_FLIGHT/UNKNOWN` as one write workflow slot each (prefix/PUT/verify sequential; UNKNOWN conservatively holds a potentially live remote write), plus all `probe_held_slots`. `VERIFIED` requires both operations settled, `FAILED_NOBYTES` requires no possible dispatch. Do not use expired leases or failed reads as evidence of settlement. New registration/probe increments its required slot under session lock; B1 transport concurrency/deadline stays an independent limit. B2 may stop indefinitely at the configured cap; tests needing retry + probe budget enough slots explicitly. No automatic release on ambiguous outcomes.

## B1 internal extension and restart reconciliation

- Coordinators use `RegisteredQuarantineStorage` (extends the existing adapter interface): `prepareRegisteredQuarantineAttempt(): { attempt: QuarantineAttempt; target: StorageTarget; maxChunkBytes: number }` (IO-free, all frozen). Bind that fresh descriptor to the adapter's canonical target **before** handing it out for registration; PUT checks existing B1 one-shot/target guard. Preserve B1 `prepareQuarantineAttempt()` and `verifyQuarantined()` behavior and regression suite. Target is exact endpoint/bucket/region, not a credential; adapters use only already operator-validated config. Never construct an SDK client or recover a PUT descriptor from a row.
- Internal-only `inspectRegisteredQuarantineObject(proof, { maxBytes, signal })`: bounded GET-only for a DB-derived opaque probe grant containing attempt ID, exact key, target, and claim ID/generation (trusted coordinator wiring, not JSON; no proof issuer in either feature barrel). Validate namespace and ID plus exact canonical target equality **before network**; no fallback. Reuse B1 bounded GET body, deadline/abort and response cap; no body returned. Result `PRESENT {actualBytes,sha256}` only on full bounded drain; one 404 may be `NOT_OBSERVED`; transport, 403, overflow, abort or malformed response → `INDETERMINATE`. Also report trusted `transportSettled` (B1 lingering/cleanup tracking, never inferred from lease/time/HTTP status alone). No new S3 operations, no GET for arbitrary keys, no old PUT, no DELETE.
- Bounded recovery sweep: candidate scan in RC, without locks, selecting eligible exact registry rows only; fresh short claim transaction per candidate locks in normal order, rechecks expiry/state/charge and budgets. Retire expired `REGISTERED` without GET; retire expired `IN_FLIGHT` to `UNKNOWN`, retaining charge. Probe `UNKNOWN` only if eligible and owner has spare live slot, one unexpired probe lease at a time for a row. Increment `probe_generation` and held slots; write fresh probe lease ID/DB-clock expiry; COMMIT and release before GET; ambiguous claim COMMIT → no GET. No URL or caller-selected key. Probe lease is a technical expiry, not limited by expired F/intent. For probe candidates prefilter exact target, expired/cleared claims and owners with spare slots before `LIMIT`; prioritize never observed then oldest observation with stable ID tie-break. Recheck all predicates under lock. Do not let an off-target or owner-budget-blocked row monopolize the bounded sweep.
- Fresh RC finish transaction matches exact row/probe generation/lease before recording one observation. If claim expired or superseded, ignore its output (including stale cleanup), and retain uncertain slot charges. An expired claim may be replaced with a new generation **only with a spare slot**; old debt is retained. On current, live result clear claim and decrement one slot only on proven local GET settle; otherwise clear claim but retain that debt. No observation shrinks physical charge, changes write state, authorizes new PUT on this key, or creates a binding. Repeated absence is not a delete proof either. Recovered object hash is **observed**, not a trusted expected PUT digest; B2 intentionally does not auto-promote after crash or even if user consent is still live. This trades recovery availability for safe accounting and no accidental publication.

Restored ACTIVE epoch 2+ returns `NOT_CONFIGURED` before producer/PUT and does not adopt an old write result. The technical GET-only reconciliation path is not a write authority.
