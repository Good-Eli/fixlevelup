## 3. Хранилище, версия и публикация

- Идентичность — UUID + canonical stable code, immutable kind и ключевые связи; корректирующее изменение связей требует новой идентичности. Company-wide catalog; category/brand/model/fault связаны реальными FK; model имеет brand+category; fault имеет category; mapping связывает fault и WORK той же категории через composite FK, не отдельная произвольная строка. Справочники и item metadata: `DRAFT` identity без опубликованной версии, publish создаёт новую immutable full revision/current pointer, `ARCHIVED` блокирует новые selections, не заменяет старые данные. Для выбора проверяются active/visible parent refs (включая model/fault mapping/eligible item), неизменяемые FK источников не удаляются. Архив не выполняет каскадных переписываний и не стирает историю. Поля `durationMinutes` нужны только WORK/DIAGNOSTICS, SQL CHECK и discriminated DTO; PART/MATERIAL и TRAVEL duration не принимают. PART — отдельное CRM представление и отдельный money component; MATERIAL — явная линия works. Code/label/description, category, unit и отдельные flags technician/public нигде не заменяют денежную версию. Критичные справочники проходят те же optimistic и audit guards.
- Храним денежные величины в PostgreSQL `BIGINT` в minor units; wire и snapshot используют канонические ASCII-строки `0|[1-9][0-9]{0,18}` с числовой границей `0…9223372036854775807`. Не принимаем цену JSON number, знак, ведущие нули или exponent. Считаем `BigInt` без преобразования денежных данных в `Number`, валюты не смешиваем. Нулевой fixed price — только с явным no-charge основанием; без active fixed row — `PRICE_NOT_CONFIGURED`, не range, другой город или global. Все price/rule/policy/range sources — `city_id NOT NULL`, FK к городу и, где хранится provenance, `(cityId,cityVersionId)` к своей immutable city version. Диапазон имеет независимую стабильную identity одного city/category/label code, min≤max, source/disclaimer; его утверждение не создаёт fixed price.
- **Одна выбранная схема интервала:** полностью append-only version table (original start/end, money и provenance) + отдельная обязательная 1:1 `*_periods` projection. Для цены это `catalog_price_periods`: `price_version_id` PK, composite FK на ту же `(version,series,city,item)`, исходные `valid_from`/`scheduled_until` сверены с version при вставке, nullable `closed_effective_until` изначально пуст. Обратный deferred FK требует projection к COMMIT. EXCLUDE `(city,item,tstzrange(valid_from,coalesce(closed_effective_until,scheduled_until),'[)'))` в проекции; для rules/ranges/policy тот же паттерн по их city-scoped aggregate key. SQL CHECK/trigger/ACL запрещают смену исходных полей, truncate/delete, искусственный initial close, повторное закрытие и увеличение интервала. UTC строго до миллисекунды (`to=null` open-ended); DB guards после lock waits, финальная проверка до COMMIT. Close только действующей записи с `now < T < scheduledEnd` (если finite) и до неё не закрытой; new publish строго future. Replace в одном tx: close at T + insert at T, expected aggregate revision, общая блокировка, один audit/outbox; при ошибке/конфликте не образуется разрыв. Зафиксированное прошлое не переписывается; standalone close намеренно прекращает будущую доступность. Неопределённый COMMIT не повод повторять запись: в 01/02 явно сверяют состояние, а в 03 точный аутентифицированный replay через durable receipt, без другого T, тела или If-Match. [Точная модель и PostgreSQL proof 01](P04-01-CONTRACT.md).
- **Независимые версии метаданных и цены.** Опубликована цена WORK на штуку, потом изменён только заголовок: новый расчёт использует **новую текущую** metadata revision для label/eligibility и **прежнюю действующую** price version; обе входят в snapshot, как и reviewed metadata revision, на которую указывает price version. `unit` неизменна на идентичности SKU: другая единица → другая позиция и собственная цена; нельзя считать старую цену за новую единицу. Архив/недоступный parent или невыполненные flags блокируют fresh selection независимо от периода. Для current price/calculation обязателен shared catalog fence отдельным первым SQL в READ COMMITTED; только следующим SQL после ожидания берём DB `pricingAt` и один согласованный snapshot city/settings/catalog/period/rules. Нет caller-supplied `at` или обхода через один MVCC-запрос. История точной неизменяемой ревизии по ID может читаться без fence, но не разрешает fresh selection. Старое вычисление воспроизводится по точным сохранённым источникам, не по текущим карточкам, периодам или timezone.
- На API со стороны staff cityId в path/query — **цель**, не authority. Валидируем scope для точной цели; записи с идентификаторами проверяются по сохранённым city/типу до версий, receipts, конфликта или возвращаемой записи. Для будущего single-city projection только server-owned [P03 resolver](../apps/api/src/settings/geography/city-context.ts), и нет «первого города». Internal reader принимает доверенную пару `cityId/cityVersionId` от конкретной серверной boundary и сверяет ownership; опция тестов двух городов не активирует второй город владельца.

## 4. Pricing contract (технический, не боевая политика)

- Входы: validated selections со стабильным уникальным line ID, exact fixed/rule sources одного city/currency, отдельные `pricingAt` и `tariffAt`, city-version/timezone, trusted express flag, явные typed adjustments. На `(cityId,pricingAt)` ровно одна опубликованная effective policy (EXCLUDE); отсутствие → `PRICING_NOT_CONFIGURED`, неоднозначность → `PRICING_CONFIGURATION_AMBIGUOUS`, отсутствие нужной цены → `PRICE_NOT_CONFIGURED`. Никакой цены, итогов или override из клиентского DTO. Adjustment evidence — доверенный вход без HTTP выдачи: точная привязка к этому контексту вычисления, adjustment/rule revision, city, policy version, базе, итоговой величине, authority/reason; запрещены дубли adjustment/evidence и конфликтующие или неполные записи. Hash не attestation полномочий. Проверяются применение within-limit и отказы при неподтверждённом overlimit; реальная выдача/проверка апрува и расходование между документами — P11, без новых `pricing.adjust` grants.
- **Количество:** каноническая ASCII десятичная строка без знака/exp/пробелов/ведущих или конечных дробных нулей, максимум 12 целых и 6 дробных цифр; строго >0. Примеры `1`, `0.25`, `12.001`; `0`, `1.0`, `01` отклоняются. `selection.unit` точно равна отдельному неизменяемому `catalog_items.unit` выбранного SKU (не `catalog_items.code`); именно код единицы определяет `maxScale` (0…6) и наличие в allowlist policy. Два разных SKU могут разделять `piece`; подстановка кода позиции вместо `piece` отклоняется. Нет автоматических conversions или default unit. Количество разбирается в `n/10^scale` без `Number`. Для unit price расчёт линии — `round(amountMinor*n/10^scale)`; никакого промежуточного округления. Все line/component magnitudes и конечный total — в границах `BIGINT` из §3; промежуточные произведения и итоговая signed формула — `BigInt`, overflow/отрицательный итог → отказ, не clamp. Пределы для доказательства bounded work: ≤128 базовых линий, ≤64 кандидатов rules, ≤32 adjustments, лимит превышен → отказ до частичного результата.
- **Правила и базы:** `EVENING`, `NIGHT`, `EXPRESS`, `SURCHARGE`, `DISCOUNT`; `FIXED` minor magnitude или `RATE` integer `1…10000` basis points (`rate/10000`), не вместе. `10000` — технический предел данного synthetic-режима, не утверждённый бизнес-максимум Q06; тесты принимают `10000`, отвергают `10001`. Промежуточное произведение не ограничивается SQL BIGINT, если округлённый сохраняемый результат помещается. Базы из **уже округлённых базовых строк без любых adjustments**: `WORKS` = WORK+MATERIAL; `WORKS_AND_PARTS` = WORK+MATERIAL+PART; `ORDER_BASE` = TRAVEL+DIAGNOSTICS+WORK+MATERIAL+PART. Category restriction оставляет только линии явно перечисленных категорий, строки без категории не попадают; пустая выборка не действует как разрешение для fixed adjustment. Inclusive `minBase/maxBase` — eligibility перед вычислением (не подменяют базу), inclusive `minDelta/maxDelta` — floor/cap уже округлённой неотрицательной magnitude перед применением знака; `min>max`, ошибочный scope или incompatible evidence → отказ. Rate: `round(base*rate/10000)`, fixed: magnitude без округления; `HALF_UP` (tie upwards) либо `DOWN` (towards zero), обязателен явно опубликованный rounding mode. У каждой линии один компонент; `total = travel + diagnostics + works + parts + time + express + approvedSurcharges − approvedDiscounts`, без дополнительного округления. Tax display explicit provenance, не налоговый расчёт.
- **Выбор правил:** версионированная policy явно задаёт порядок и совместимость; движок не зашивает победителя. Для temporal group (EVENING/NIGHT) допускается максимум одно правило, для EXPRESS тоже максимум одно. Из подходящих выбирается только единственный явно высший priority; равенство/отсутствие достаточного приоритета → `PRICING_CONFIGURATION_AMBIGUOUS`, не tie-break по UUID. Synthetic fixture по [ТЗ §6.5](../info/ТЗ.md#L365-L380) проверяет явную политику «NIGHT выше EVENING», а не обязательный runtime default или решение о тарифном instant. Парное stacking только по explicit allow, в том числе EXPRESS+time; при нескольких несовместимых оставшихся кандидатах без однозначного разрешения расчёт отказывает целиком. Adjustments от мастера нет. Stable ID служит только каноническому порядку сериализации. Local window `[start,end)` в минутах, midnight wrap явный, `start=end` недопустим (отдельный явный all-day, если нужен); DST repeated hour разрешается исходным UTC instant, выбор UTC для визита — P09/Q10.
- **Snapshot v1:** canonical normalized plain data, проверка формы и order, breakdown/lines/raw numerator/denominator/base/rounding/limits/reason/evidence, current metadata+original reviewed revision+exact fixed/rule/policy revision, city/version, currency/tax, оба UTC instant, IANA timezone, вычисленные локальные дата и время + смещение в секундах, признаки и результаты матчинга правил. Новый расчёт использует текущую tzdata и фиксирует результат преобразования; при повторе используем сохранённую локальную проекцию (проверяем связь `UTC instant + offset = local wall time` и заново применяем сохранённые окна), не текущую tzdata/справочники. `SHA-256` сверяется с доверенно сохранённым digest для integrity; пересчитанный самим клиентом SHA не доказательство происхождения. Deep-copy/freeze и fail-closed на некорректных границах, смешанных компонентах и чужих sources. Проверить переименование, repricing, архив и подмену текущей tz-логики с сохранением старого результата. Это не принятая смета; без fake quote/customer tables.

## 5. Staff API, авторизация, CRM и OpenAPI

Кандидат capability matrix: `catalog.read/manage` (COMPANY); `pricing.rules.read/manage` (COMPANY, только definitions); `pricing.read/manage` (CITY или GLOBAL, только city target); `content.external-reviews.read/manage/publish` (COMPANY). Write требует matching read+manage; Avito publish требует ещё exact publish; создание диапазона/тарифа или точной цены — явная publish команда write pair, не generic PATCH `price`. Мастер (SYSTEM TECHNICIAN или TG channel) не получает P04 staff grants/CRUD. Позднее read-only T selection будет через request-scoped P11, не общая P04 staff history. GLOBAL только SYSTEM ADMIN; CUSTOM-web/manager могут получить явные CITY-grants на prices только c действующим admin-city assignment. COMPANY операции — SYSTEM ADMIN GLOBAL по отдельным кодам; разрешение редактировать цены одного города не разрешает редактировать общие definitions/каталог/публикации. Права из role catalog/claims или P03 не наследуются; city discovery выдаёт только допустимые city IDs/labels для конкретной операции. New/extended grant/присоединение требует собственного exact GLOBAL; нельзя делегировать через «имею доступ на эту страницу». Role grant UI предупреждает о действии на всех членов роли. Миграция добавляет код и guard metadata, но не выдаёт его. Предлагается явное offline provisioning отдельного отзывного персонального источника (проверенный исходный bootstrap assignment under same policy lock, не каждый SYSTEM ADMIN, не новый login/recovery/reassignment, без bulk/role writes; вызвать только на fresh synthetic тестовой БД); живое применение потребует отдельного разрешения. Права P03 и replay существующих миграций не меняются.

- Web cookie/Origin/CSRF и protected transaction повторно используют P03 security primitives, `rbac` policy lock, lock ordering, свежий DB clock после последнего wait на readiness/target/receipt и до начала эффекта; перед ответом/commit повторная проверка identity/role/live scope at DB time, current signed-in actor, expiry. Domain writes + safe audit/outbox + durable receipt в одной tx. Failure before commit rolls back all; uncertain COMMIT → явный exact retry (тот же actor/operation/canonical target+body+If-Match/key), API не делает повтор автоматически. Replay авторизует requested и stored target/required exact codes прежде чем раскрыть 409/412/receipt; identities и history не раскрываются чужим scopes. Для receipt SHA-256 считается из точно той же строго декодированной, нормализованной и неизменяемой команды, которая исполняется (включая locked target и precondition). Текстовые JSON-входы HTTP и snapshot v1 отклоняют дубли **декодированных** ключей до потери информации обычным парсером (`"unit"` и `"\u0075nit"`), недопустимые представления чисел и лишние поля; отдельные отрицательные векторы обязательны. Никаких raw texts/URL/amounts/SQL/credentials в логах, audit/outbox metadata only. Routes use projection with safe status errors; authenticated reads `Cache-Control: no-store`. Mutation `Idempotency-Key` + strong `If-Match: "p04-vN"` except create (I only); receipt structurally bounded with IDs/versions only. Advisory lock keys/ordering не меняют P03. Narrow ACL, tenant migration scope none.
- Уточняемые в контракте slice 03 пути (под `/api/v1`): `/catalog/{categories,brands,models,faults,items,fault-service-mappings}` — отдельные typed resources, no dynamic table CRUD; `/{id}` и `/versions[/{versionId}]` history, `.../versions` publish, `.../archive` явный lifecycle. CITY paths `/pricing/cities/{cityId}/{items/{id}/price-versions,rules/{id}/versions,policy-versions,public-estimates}` + checked exact history/publish/close paths; `/pricing/rules` definitions; P03 canonical geography paths, без новой zones DB, при наличии legacy alias — тот же command/guards. `/content/external-reviews` — ручные Avito entries, профиль и отзывы раздельно, versioned create/publish/archive; ограниченный HTTPS URL allowlist `avito.ru`/`www.avito.ru`, normal form без credentials/портов/query/fragment и перенаправлений, без network side effects; plain text excerpt/date/nullable rating, explicit reviewed permission evidence bound to revision (fixture not real permission), source/change history. Без profile/review authorization → нет публикации. Никакого скрейпинга/Avito API/upload, никто не исполняет HTML, сам внешний URL не скачивается. Public projections остаются выключены.
- Один структурный OpenAPI 3.1 artifact с named schemas, cookie/CSRF/I/V, enum/bounds/errors/paging/route IDs; deterministic typed client generation без новых runtime deps, verify generated drift и contract tests HTTP allow/deny/backwards compatibility. Exact DTO shape on server+browser; no generic JSON editor. Списки: bounded keyset (`limit` default 20/max 50; `LIMIT limit+1`), стабильные `(code,id)` для идентичностей, `(version,id)` для версий, направление и все фильтры фиксированы для каждого route; opaque cursor v1 ≤512 ASCII bytes привязан к resource type, normalized query/filter, parent id и authorized city target. Cursor не является authority; malformed/cross-resource cursor отклоняется, каждый запрос заново проверяет target scope. Request JSON только UTF‑8, максимум 16 KiB для обычной команды, 64 KiB для policy с ограниченными arrays, 12 KiB для Avito (excerpt ≤1500 code points, URL ≤2048 ASCII bytes, дополнительно ограничения DTO); лишние поля, неверные типы и превышение лимитов — отказ. Slice 03 закрепляет для каждой операции exact cap, response cap и pagination/error contract. Typed client generation не требует нового runtime SDK; новая внешняя зависимость только по отдельному решению.
- Client uses dedicated scoped city list, exact resource IDs и revision-based forms; after stale/revoke keeps editable draft only in memory with clear result, on actor/session change aborts/discards previous responses; no `localStorage`, no unauthorized cache. Shared policy kernels не дублируются, disabled controls не являются authority. Отдельные discriminated формы/DTO для `PART` и `MATERIAL`; `MATERIAL` не может попасть в PARTS или получить duration. `Publish` диапазона, Avito profile/review — **внутреннее утверждение неизменяемой версии**, не показ на сайте и не публикация на Avito; нет публичного route, сетевого вызова или обхода live gate.
