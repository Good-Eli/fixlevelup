# Подэтапы проектов: журнал актуализаций

Живой рабочий файл. Здесь хранятся таблицы подэтапов по каждому проекту в том
виде, в котором они были актуализированы по запросу владельца. При последующих
просьбах «актуализируй» раздел соответствующего проекта дополняется или
обновляется; завершённые подэтапы не удаляются и не переписываются задним числом.

Источник фактов: `git log`, миграции в `prisma/migrations/`, README пакетов,
[ROADMAP](ROADMAP.md), [DECISIONS](DECISIONS.md), [CHANGELOG](../CHANGELOG.md).
Таблицы ниже — сводка для чтения, а не замена этим документам.

Нумерация `P0X-NN` берётся из [ROADMAP](ROADMAP.md). Для P01 подэтапы `P01-01.*`
и `P01-12*` зафиксированы в README пакетов и комментариях миграций; для P02
подэтапы `P02-01…P02-06` определены таблицей в [ROADMAP §P02](ROADMAP.md#p02--сотрудники-auth-и-capabilities).

## P02 — сотрудники, Auth и capabilities (в работе)

Ветка `main`, база журнала — HEAD `02766f6` (16 коммитов). Разрешён документальный
`P02-01`; дальнейшие подэтапы открывались отдельными разрешениями владельца.

| № | Название | Что это и зачем в общей картине | Статус |
|---|---|---|---|
| **P02-01** | Contracts & Minimal Access Model | Договорённость, кто и как входит в систему: администратор и менеджер — в веб-кабинете, мастер — через Telegram Mini App, клиент — через TG/VK/MAX. Фиксирует, что сам канал входа не даёт прав и что права сотрудника отделены от прав клиента на конкретную заявку. Только документы, кода нет. | ✅ |
| **P02-02** | Учётные записи и bootstrap | Первые настоящие учётные записи сотрудников: карточка сотрудника с ролью и состоянием, веб-логин с паролем, метка «первичная настройка уже выполнена». Одноразовая консольная команда создаёт первого администратора — без пароля по умолчанию и без открытой регистрации; вторая команда меняет забытый пароль. Пароль хранится только как необратимый Argon2id-хеш. | ✅ (`02766f6`) |
| **P02-03** | Веб-аутентификация M/A | Вход менеджера и администратора в кабинет: логин, «кто я», продление сессии, выход, смена пароля. Сессия — случайный токен в защищённой cookie, в базе лежит только его хеш; число попыток входа ограничено, чтобы перебор не работал. Смена пароля гасит остальные сессии. | 🔄 в работе |
| **P02-04** | Общая серверная авторизация | Одна общая проверка прав на каждом запросе: кто ты, какая роль, что именно разрешено, к какому объекту. Отказ по умолчанию, запрет выдать себе больше прав, чужая заявка не открывается по подмене идентификатора. | ⏳ не начато |
| **P02-05** | Telegram-аутентификация мастера | Мастер открывает Mini App, сервер проверяет подлинность данных Telegram и наличие заранее созданной активной связи с сотрудником — и выдаёт отзываемую сессию. Без автоматического веб-логина; подделка, просрочка и повтор не проходят. | ⏳ не начато |
| **P02-06** | Жизненный цикл и security-регрессия | Увольнение, блокировка и смена прав должны реально закрывать все входы сотрудника, а история — сохраняться. Плюс сквозная проверка, что устаревшая сессия, чужая заявка, подделанный запрос и одновременные «отзыв + запись» не дают доступа. | ⏳ не начато |

### Что фактически есть в дереве по P02-03

Код написан и подключён; подэтап подготовлен к приёмке.

- `apps/api/src/auth/web-auth.service.ts` — вход, проверка сессии, продление,
  выход, смена пароля; хранение только SHA-256 хеша токена; ограничение попыток
  по логину и по источнику.
- `apps/api/src/auth/web-auth.controller.ts` — маршруты `POST /auth/login`,
  `GET /auth/me`, `POST /auth/renew`, `POST /auth/logout`, `POST /auth/password`;
  cookie HttpOnly/Secure/SameSite, проверка Origin и CSRF.
- `apps/api/src/auth/web-auth.config.ts` — обязательные `WEB_AUTH_ORIGIN`,
  `WEB_AUTH_CSRF_SECRET` и `WEB_AUTH_THROTTLE_SECRET`; при выключенном
  `WEB_AUTH_ENABLED` маршруты не регистрируются.
- `apps/api/src/staff/password.ts` — общий модуль Argon2id, вынесен из bootstrap.
- `prisma/migrations/20261120000500_web_auth/` — таблицы `web_sessions`
  и `web_auth_throttles` с column-level GRANT для runtime-роли.
- Тесты: `apps/api/tests/web-auth-integration.test.ts`,
  `apps/api/tests/web-auth-http.test.ts`, `apps/api/tests/staff-password.test.ts`
  и opt-in `web-auth-e2e`/`web-auth-readiness` под `FIXLEVELUP_BOOTSTRAP_ISOLATED_DB_TESTS=1`.
- Обновлены `apps/api/src/app.module.ts` (контроллер и провайдеры),
  `prisma/schema.prisma` и `packages/database-tooling/scripts/test-migrations.mjs`
  (пятая миграция в цепочке fresh/upgrade/replay).

Незакрытым остаётся только приёмка подэтапа владельцем.

### Открытые gates P02

- **Q12 согласован для web-сессий.** Владелец утвердил idle 30 минут, absolute
  12 часов, атомарный renew с ротацией без продления absolute TTL, а также
  пять неудач по идентификатору за 15 минут с дополнительным source-лимитом
  ([DECISIONS §21](DECISIONS.md#открыто-до-соответствующей-реализации)).
  Остальные части Q12 (staff/F/link-сессии и повторный обмен initData) открыты.
- **Матрица role × capability × scope** (§13) остаётся на согласование — она
  нужна для `P02-04`.
- **Ручная проверка CLI в живом терминале** (P02-02) не выполнена: скрытие
  пароля, подтверждение, Backspace, несовпадение, Ctrl+C. Обязательна перед
  первым реальным использованием bootstrap/recovery.
- **Мастеру веб-пароль не создаётся** — это правило, а не недоделка.

### Дальше

Порядок жёсткий: `P02-04` требует согласованной матрицы прав, `P02-05` —
согласованного TTL и proof привязки, `P02-06` — готовых `P02-03/04/05`.
Каждый следующий подэтап запускается только по отдельному разрешению владельца.
