## Данные и SQL-инварианты

- В `foundation`: `catalog_directory_entries(id,kind,code,category_id,brand_id,row_version,current_version_id,archived_at)`, `catalog_directory_versions(id,entry_id,version,title,description,reviewed_by,published_at)`. `kind` ∈ CATEGORY/BRAND/MODEL/FAULT. CATEGORY/BRAND не имеют parent, MODEL имеет CATEGORY+BRAND, FAULT — CATEGORY only. Real typed self-FK `(category_id,category_kind)` и `(brand_id,brand_kind)` к `UNIQUE(id,kind)`: bind фиксированных discriminator defaults/constraints, не свободный input. `(id,kind,category_id)` также уникален для same-category mappings. `(kind,code)` unique, `code` lower ASCII slug 2..64; UUID не переиспользуется. CHECK не полагается на unknown/null для required branch.
- `catalog_items(id,kind,code,category_id,unit,row_version,current_version_id,archived_at)`, `catalog_item_versions(id,item_id,kind,version,title,description,duration_minutes,technician_visible,public_visible,reviewed_by,published_at)`. Код globally unique у items, kind enum WORK/PART/MATERIAL/TRAVEL/DIAGNOSTICS. CATEGORY required для WORK; для остальных optional (если указана, typed FK). `unit` immutable canonical slug (1..24, никакого default); изменившаяся единица требует **другой SKU**, новую цену, архив прежнего по отдельной команде. v1 принимает только whole minutes 1..1440 для WORK/DIAGNOSTICS (required); остальные duration отсутствует. title 1..160, description опционален ≤1000, no control/format chars в wire нормализации; flags явные boolean, значение по умолчанию не подставляется. Version chain `(entry/item_id,version)` и pointer `(id,current_version_id)` к своей истории; item version также typed FK `(item_id,kind)`. DRAFT = null pointer и no archive; архив terminal, pointer остаётся; новый publish требует active parents, P04 не переписывает существующие FK/слайсы каскадом. Version sequence 1+ и row_version CAS 1+; canonical pointer progression и неизменность stable fields под trigger/ACL. Append-only versions deny update/delete/truncate.
- `catalog_fault_service_mappings(id,category_id,fault_id,item_id,row_version,published_at,published_by,archived_at)` — pair unique, fault FAULT + item WORK того же CATEGORY по NOT NULL composite FK `(id,kind,category_id)`. Фиксированные discriminator columns допустимы, не принимаются в input. DRAFT → PUBLISHED одной парой `published_at/published_by`; terminal archive может убрать draft или published; история identity и первого publish остаётся. Смена пары создаёт новую identity, не PATCH. Нет `DELETE`/reactivate. Fresh selection требует опубликованные/неархивные mapping, fault, item и category; если item нужен мастеру/для будущей public projection, additionally matching visibility, не authority.
- `catalog_price_series(id,city_id,item_id,row_version)` unique `(city_id,item_id)` и `(id,city_id,item_id)`, hard FK для обеих сторон. **Полностью append-only** `catalog_price_versions(id,series_id,city_id,city_version_id,item_id,item_version_id,version,amount_minor,currency,zero_basis,source_ref,reviewed_by,published_at,valid_from,valid_until)`; same-city `(city_id,city_version_id)`, same-item `(item_id,item_version_id)`, triple series composite, unique `(city_id,id)`, `(series_id,version)` и `(id,series_id,city_id,item_id)`. PostgreSQL `BIGINT 0..9223372036854775807`; wire canonical decimal string; 0 iff explicit nonempty `zero_basis`. Currency `[A-Z]{3}` syntax only, no default; source/zero reason nonblank ≤200. Price points to the reviewed item revision. After a title-only edit the fresh reader returns **new current metadata, same price version and its original reviewed item revision**. Same immutable unit; different unit requires a separate SKU and price. Visible item and category must be published/unarchived. Prices may be prepared for a city with a published current version; a fresh offer requires ACTIVE and compatible trusted city context. No fallback or business readiness.
- **Exact one-to-one interval projection:** `catalog_price_periods(price_version_id PRIMARY KEY,series_id,city_id,item_id,valid_from,scheduled_until,closed_effective_until)`; composite FK `(price_version_id,series_id,city_id,item_id)` → the exact version; invoker INSERT trigger checks equality of start/end with that version (NULL-safe) and requires initial closure NULL. Reverse FK `catalog_price_versions.id` → `catalog_price_periods.price_version_id` is `DEFERRABLE INITIALLY DEFERRED`; order: insert version, insert projection, finish one transaction. No orphan/incomplete version after commit, no duplicate projection; trigger and column ACL make identity and original period immutable, projection cannot be deleted/truncated/reinserted. GiST EXCLUDE `(city_id WITH =,item_id WITH =,tstzrange(valid_from,coalesce(closed_effective_until,scheduled_until),'[)') WITH &&)` with trusted server-provided `btree_gist`; verify fresh/upgrade/shadow and real 23P01. Prefer named exclusion constraint and pinned schema-qualified extension operator classes. `valid_from`, original `valid_until`/`scheduled_until` and `closed_effective_until` are finite, millisecond-aligned (`timestamptz(6)` + CHECK, no silent rounding). Canonical input UTC ISO `YYYY-MM-DDTHH:mm:ss.sssZ`. `valid_until` null or strictly after start.
- **Astra M01, terminal close/replace.** Clock after shared lock order, compare-and-set on the same `(city,item)`; future publish `start > floor(db_clock_ms)`, close only previously open & effective (`start≤now<scheduledEnd` or no end), require `T>now` and `T<scheduledEnd` if finite; only `closed_effective_until` NULL→T. SQL write guards + deferred final clock check on changed projection(s) reject a scheduled boundary crossed during waiting/evidence; no claim of pinning wall-clock to network COMMIT acknowledgement. Writer fence stays held through transaction end; current-price decisions take the matching shared fence and sample DB time after it. Replace in one tx closes old projection at T and inserts new version+projection starting exactly T, bumps CAS once; stale/overlap/audit/outbox failure rolls back both, no old-period gap. Standalone close intentionally ends future availability. Cannot close scheduled-unstarted/expired/already closed rows, prolong or backdate. Initially expected 0; first publish inserts series at v1, no free standalone series/create seed via a port; later publish/close/replace bump CAS once. New version sequence can use next series CAS (gaps after standalone closure). Unknown COMMIT in 01: verify exact persisted series/price/projection, no auto retry, expected version fences a repeated effect; 03 adds exact authenticated replay receipt.
- Least privilege: `fixlevelup_runtime` SELECT named new tables (including strict readers), INSERT just supplied columns; UPDATE subset pointer/archive+version for mutable parents, mapping publish+archive, series version and `catalog_price_periods.closed_effective_until` only. **No UPDATE on the price version table**; forbid owner DML changes to immutable history. Trigger functions invoker/search_path pinned, no DELETE/TRUNCATE, no security-definer issuer, no broader existing grants or install-time business data. SQL catalog for CHECK/constraints/ACL, direct cross-city/exclusion/projection/close tests as well as Prisma drift (which alone cannot prove unsupported constraints).

## Internal port contract and tests

Paths `apps/api/src/catalog/`: contracts, strict validation, transaction/audit, directory/items/mappings writes, prices/reads. All write methods require one caller transaction through `Pick<PoolClient,'query'>`, verified before side effects (not auth; only trusted code passes `reviewedBy`). Receipt shapes `{id,version}` or `{id,version,revisionId,revisionVersion}` (price `id=series`), publish/price inputs are discriminated request types. Use parameterized SQL; no DTO passing model column/control ids. Mutating op order: caller RBAC later → `pg_advisory_xact_lock(77304,1)` before any catalog/city DB reads/locks → referenced current city row `FOR SHARE` if needed → CAS / writes → allowlisted safe audit+outbox in same tx; no call into company-lock or other existing command from inside catalog mutation. Lock intentionally coarse for small P04 workshop. Each direct permitted INSERT/UPDATE also takes the same exclusive transaction fence in a BEFORE STATEMENT trigger; catalog mutation requires READ COMMITTED. Direct DML does not provide application actor audit/receipt. The runtime principal is trusted, cannot be exposed to staff or used to run caller-selected SQL/force early constraint evaluation. `clock_timestamp()` consulted after final lock wait; exceptions must abort/force rollback, even if caller catches an application validation error after any write (savepoint wrapper or equally strong invariant). Fresh `readFixedPrice` (и composed current pricing reader P04-02) требует caller transaction **READ COMMITTED**, отдельным первым SQL получает `pg_advisory_xact_lock_shared(77304,1)` и удерживает до конца tx. Только **следующее** согласованное чтение PostgreSQL после ожидания берёт `pricingAt = date_trunc('milliseconds',clock_timestamp())`, city/version, eligibility и sources. Нельзя использовать timestamp до fence, browser `at`, `transaction_timestamp()`, снимок REPEATABLE READ, захваченный до ожидания, или один MVCC запрос без fence. Выбор нескольких источников для расчёта P04-02 использует одно DB snapshot и `pricingAt`, без смешивания с geography, которую сам catalog fence не блокирует. Fresh lookup accepts exact trusted city context/version; returns chosen DB `pricingAt`, explicit `PRICE_NOT_CONFIGURED` vs bad source and canonical decimal string. For exact named immutable revisions only, a fence-free ownership-checked query is allowed; it may return immutable original bounds, not infer live availability/closure; old calculation replays sealed values separately.
