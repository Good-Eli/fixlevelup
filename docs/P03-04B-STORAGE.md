## Точная граница этого среза

Только низкоуровневый private S3 adapter/config и synthetic контрактные тесты. Это **не** авторизованный upload endpoint, не регистрация файла/попытки в БД, не QUARANTINED/READY transition, не scanner/sanitize/download/access/delete и не завершение P03-04B. До подключения к business workflow нужна durable попытка с зарегистрированным exact key, lease/fencing, основанием и состоянием; текущий adapter не заменяет ни одно из этих условий. Runtime dependency approval не разрешает реальные форматы/квоты/TTL/PII.

## Общий API для реализации и тестов

`apps/api/src/files/storage/index.ts`:

- `createPrivateQuarantineStorage(config)` → adapter; constructor/factory не делает network IO.
- `prepareQuarantineAttempt()` → server-generated one-shot internal descriptor `{attemptId, objectKey}` (opaque brand допустим, не JSON/browser authority). Namespace `quarantine/<randomUUID>/<randomUUID>` без имени/PII/сырого client key. До byte IO future coordinator обязан зарегистрировать exact descriptor в БД; adapter standalone пока не подключён к бизнес-пути. Тестовые descriptors only synthetic.
- `putQuarantined(attempt,{body:AsyncIterable<Uint8Array>, expectedBytes:number, maxBytes:number, signal:AbortSignal})` → `{attemptId,objectKey,actualBytes,sha256}` только если PUT и фактический bounded iterator завершились успешно; без URL/ETag как checksum. Это внутренний storage receipt, не public DTO и не READY. Expected/max bytes обязательны (политика не придумывается); safe positive integers, expected<=max. Каждый исходный chunk копируется до hash/push, поэтому caller mutation не меняет отправленные байты. Счётчик/хеш actual bytes, reject nonbytechunk/tooMany/tooFew, отмена обрывает stream/socket. Ограничены maxChunkBytes и maxConcurrentOperations, включая незавершённые транспортные операции после deadline. Source ошибки не эхо-ятся.
- `verifyQuarantined(attempt,{expectedBytes,sha256,maxBytes,signal})` → internal same byte/hash receipt после bounded GET/read и сравнения actual bytes/hash; HEAD/metadata/ETag недостаточны. GET доступен только по собственному descriptor namespace, не произвольному key или URL. Это проверка хранилища, не выдача содержимого клиенту.
- `close()` освобождает client/agent resources, запрещает новые операции и prepare на закрытом instance, aborts/waits активные SDK операции. Отдельная operation deadline действует на полное GET body после headers. Контракт не обещает остановить произвольный caller iterator, который игнорирует отмену; транспорт и SDK sockets должны быть закрыты/settled, source return вызывается без бесконечного ожидания.

Интерфейс может уточняться исполнителем по фактическому SDK API, но export names/структуру нужно сразу сообщить независимому тестовому агенту. Не использовать `@aws-sdk/lib-storage`/presigner/Sharp или transient imports как скрытые новые deps.

## Конфигурация

Closed typed object `mode,endpoint,allowedEndpoint,region,bucket,accessKeyId,secretAccessKey,connectionTimeoutMs,requestTimeoutMs,socketTimeoutMs,operationTimeoutMs,maxChunkBytes,maxConcurrentOperations,maxResponseBodyBytes` — все обязательны, без ENV/default credential chain/metadata service; maxAttempts=1, forcePathStyle=true, bounded transports. Активен только `mode=local-synthetic`: literal HTTP `127.0.0.1` с явным port 1…65535 и точным совпадением с отдельно заданным `allowedEndpoint` (3900 для Garage, явный ephemeral endpoint для transport fixtures); без DNS/localhost/wildcard. Production в B1 явно отклоняется, даже если endpoint HTTPS. Mode и ресурсные лимиты не подразумеваются по умолчанию; никаких credentials/query/fragment/path в endpoint, redirects/SSRF endpoint не принимается от user. Bucket/region bounded; `maxResponseBodyBytes` — обязательный технический cap служебных response bodies до SDK serde (любые error bodies и ответы PUT), не business quota. Payload успешного GET ограничивается отдельно явным `maxBytes` проверки содержимого. Secret-bearing validator/normalized type остаются внутренними, не экспортируются из входного index; secret не возвращается/logged. Config module не читает ignored dev dotenv в production; fixture использует существующие credentials отдельно.

Фабрика не изменяет bucket grants/website/infra; приватность bucket проверяют real Garage tests. Adapter не экспортирует CreateBucket/LIST/DELETE/presign/public URL. `Cache-Control:no-store` относится к будущей HTTP-выдаче, которой здесь нет.

## Immutable attempt и неопределённый PUT

Каждый descriptor допускает один PUT в процессе (включая разные adapter instances, module-wide consumed identity); повтор descriptor после старта PUT отказывает без новой записи. Каждый retry получает **новый случайный descriptor/key**, ни success, ни timeout не переиспользуются. `If-None-Match:*` допустим только если Garage действительно поддерживает и доказано тестом; без доказательства не обещать атомарный create-only в хранилище. In-process consumed descriptor не равен durable global fencing: после restart coordinator обязан взять новый зарегистрированный key, не восстановить descriptor и повторить PUT. Internal descriptor не принимается из произвольного serialized object.

Ошибка/timeout/abort после начала отправки → typed `WRITE_OUTCOME_UNKNOWN` (объект мог появиться позже), не «не записано» и не разрешение переписать key. Никакой автоматической очистки/DELETE или retry старого key; future orphan reconciliation требует durable attempt registry. Даже success receipt не делает объект доступным/READY. Изменения и failures не содержат raw SDK error, key/URL/credentials в error message/log.

- Unit: invalid/missing config, отсутствие default creds, no-IO factory, input byte limits, closed/consumed descriptor, shape-only borrowed descriptor rejected, safe error envelope (no raw credentials/URL).
- Real Garage: unique synthetic quarantine namespace; actual PUT→bounded GET exact bytes/hash; anonymous/wrong credentials forbidden; read-only PUT forbidden; повтор descriptor не overwrites; новое attempt не меняет старые bytes. - Transport real loopback fixtures: отказ до headers, stalled upload source/body, abort, tooFew/tooMany bytes, network failure after send — bounded settle, no leaked sockets/unhandled rejection/лог secrets. Таймеры — explicit technical config, не policy defaults.

## Адресная доработка после ASTRA

1. Попытка привязывается к immutable canonical storage target endpoint/bucket/region при PUT; verify через другой target отклоняется до сети. Module-wide one-shot PUT между экземплярами сохраняется.
2. Все error bodies и body успешного PUT ограничиваются до SDK-десериализации (она сама читает body до возврата `send`). Новый обязательный технический config `maxResponseBodyBytes`, без новых зависимостей; chunked error без Content-Length и большой неожиданный PUT response доказывают раннее прекращение чтения/закрытие socket, без success receipt.
3. Secret-bearing normalizer/validated config не экспортируется из входного index; наружу не возвращаются credentials. Входной тип конфигурации остаётся contract для конструктора.
4. Proxy reflection/iterator construction failures не прокидываются как caller Error или caller-created PrivateStorageError; только новые fixed code/reason без marker/cause. Негативные регрессии проверяют все такие пути.
