## C2. Контракты, READY и reauthorization

Ниже исходный эскиз, не действующие сигнатуры. Реализация выдаёт из processing только минимальную квитанцию; отдельная access policy управляет READY metadata, а exact scan evidence хранится в неизменяемой публикации. В актуальном synthetic профиле новые B/C записи допускаются только в исходной ACTIVE epoch 1 (legacy B без singleton — на полной схеме); restored epoch 2+ не даёт права на новые операции B/C.

```ts
// Эскиз закрытого internal API; policies и IO-инстансы только trusted wiring.
type FFile = { session: FileOwnerSessionProof; intentId: UUID };
type Digest = { bytes: number; sha256: Sha256 };
type Verdict = { kind: 'CLEAN'; content: Digest; engineBuild: string; defsDigest: Sha256; policyDigest: Sha256 }
  | { kind: 'BLOCKED' | 'INDETERMINATE'; reason: ScanReason };
type ReadyView = { fileId: UUID; state: 'READY'; mime: ImageMime; bytes: number };
processQuarantine(ctx: ProcessingContext, cmd: FFile & { signal: AbortSignal }): Promise<ReadyView>;
readReadyMetadata(ctx: AccessContext, cmd: FFile): Promise<ReadyView>;
openReadyStream(ctx: AccessContext, cmd: FFile & { signal: AbortSignal }): Promise<ReadyReadTicket>;
readReadyChunk(ticket: ReadyReadTicket): Promise<{ kind: 'CHUNK'; bytes: Uint8Array } | { kind: 'EOF' }>;
closeReadyStream(ticket: ReadyReadTicket): void;
```

1. Под короткой primary `READ COMMITTED`: session → current legal document → intent → privacy guard → attempt/publication rows в детерминированном порядке. При доступе/публикации после последнего ожидания заново проверить DB `clock_timestamp()`, raw F proof, тот же current unrevoked GIVEN/document-version/purpose, intent not cancelled, policy/session/intent и explicit access window live, отсутствие delete/restore barriers. Не сохранять raw F proof; processing запускается синхронной внутренней командой F (не фоновой job с сохранённым токеном). `GIVEN → REVOKED → GIVEN` не перепривязывает старую попытку.
2. Новый private GET с opaque single-use claim для **точной** verified raw строки; [B2 probe grant](<../apps/api/src/files/storage/registered-proof.ts#L64-L100>) возвращает только observation и не годится как content authority. Проверить HTTP 200/no Content-Range/size/полный digest, отдельную копию bounded bytes, сканировать raw **до** decode. Никаких arbitrary object keys/URL, forged JS descriptor или caller-supplied verdict. Не удерживать DB client/lock на GET, worker или send.
3. Открыть только разрешённые буферные libvips loaders ([block/unblock](https://sharp.pixelplumbing.com/api-utility/#unblock)); [strict options](https://sharp.pixelplumbing.com/api-constructor/): `failOn:'warning'`, explicit `limitInputPixels`, `limitInputChannels`, не `unlimited`; сверить signature+decoded format, размеры/каналы/число кадров до re-encode, отклонять animation/multipage (не молча брать первый кадр). Полный decode → применить ориентацию → новые pixels в выбранном JPEG/PNG/WebP encoder; ни `keepMetadata`/`withMetadata`, ни копирования чанков EXIF/XMP/IPTC/ICC/комментариев. Контроль формата/схемы метаданных и размеров выхода; цель — удалить metadata, не доказать отсутствие персональной информации в самих пикселях.
4. Новая additive migration (следующая после 015): `file_privacy_controls` по intent (эпоха, processing/retention/delete fences), `file_sanitized_attempts` (отдельный immutable key `sanitized/<attempt UUID>/<nonce UUID>` и точно зарегистрированный target), `file_publications` (immutable FK к raw binding и exact verified sanitized bytes+digest), `file_scan_evidence` (raw/served digest, verdict engine/DB/policy). Extend B storage wiring bounded operations; **составной FK**, запрещающий подменить tuple или заменить content публикации. READY — видимость неизменяемой публикации под текущими guards, не мутация A/015 и не success от одного PUT. No ACL widen/DELETE history, новые runtime column grants проверять отдельно.
5. Просканировать конечные bytes **отдельным запуском**; новый sanitized descriptor+charge/lease/generation, register COMMIT → reauthorize/dispatch COMMIT → единственный PUT → bounded independent GET HTTP 200 без Range → size/hash равны просканированному exact output. Публикация/вердикты/audit/outbox одной транзакцией и reauth после последнего lock. Commit-loss: заново доказать точный committed outcome без старого PUT. Все raw/sanitized attempts и live debt учитывать **суммарно** под session lock во всех targets, включая unbound/UNKNOWN. `FAILED_NOBYTES` лишь если не было dispatch.
6. Для чтения (не для простого metadata) сначала bounded полный GET **в отдельный private RAM buffer под явным total cap**, подтвердить digest публикации **до первого выданного байта**. Не выпускать bytes, пока заливавшийся/подменённый GET не дочитан; это проще стратегии signed chunk hashes и позволяет fail closed при tampered store. `ReadyReadTicket` — WeakMap/brand, nonserializable, свой owner/basis/publication epoch, expiry и pool/concurrency budget; issuer не в barrel, максимум один live stream на publication в synthetic профиле (short fenced DB claim), один in-flight `readReadyChunk` на ticket, таймаут и закрытие на abort/EOF/deny. Не принимать callback, инициирующий неконтролируемый prefetch/send.
7. На **каждую** порцию, включая первую после GET, отдельное короткое admission primary RC под key order выше с fresh DB clock после read/lock; сохранить только offset и immutable binding, выдать отдельную bounded копию после подтверждённого COMMIT. Не повторять admission при ambiguous COMMIT; сначала назвать результат deny и закрыть. `readReadyMetadata` проходит ту же авторизацию после exact row read; missing/foreign одинаковый `NOT_FOUND`; на отказах нет size/mime/status hints. После committed revoke следующие порции не допускаются; одна уже допущенная может дойти позднее. Consumer ждёт backpressure перед следующим вызовом; порции не помещаются в очередь. Наружу нет ключа, digest, scanner output, токена, URL; staff/HTTP/signed URL отсутствуют.

## D. Retention, hold, DELETE и проверяемый restore

```ts
type DeleteStage = 'OPEN' | 'PENDING_LEDGER' | 'LEDGERED' | 'VERIFY_PENDING' | 'CONFIRMED_ABSENT';
type RetentionPolicy = LocalSynthetic & { versionId: UUID; sourceRef: string;
  rawBoundMs: number; readyMs: number; quarantinedMs: number; orphanMs: number;
  maxBatch: number; claimMs: number; reconcileMs: number };
type LedgerEvent = { namespace: UUID; seq: bigint; eventId: UUID; prev: Sha256;
  intentId: UUID; tombstoneEpoch: bigint; items: readonly ExactStorageAttempt[] };
type LedgerHead = { namespace: UUID; seq: bigint; chainHash: Sha256; challenge: Nonce; signature: Bytes };
planRetention(ctx: PrivacyContext, policy: RetentionPolicy, signal: AbortSignal): Promise<AggregateOnly>;
applyHold(ctx: OperatorContext, grant: HoldGrant): Promise<HoldReceipt>;
executeDeletion(ctx: DeleterContext, grant: CommittedDeleteGrant): Promise<AggregateOnly>;
rescrubRestore(ctx: RestoreContext, bundle: SignedSnapshotManifest): Promise<RestoreGateReceipt>;
```

- Typed, trusted policy; explicit DB-clock anchors `raw bound/READY published/quarantined/dispatched` by class, no defaults. First synthetic implementation uses **intent-wide** hold and collapse of eligible expired/cancelled/abandoned files to one tombstone; never arbitrarily delete a raw derivative of a still-live publication. Separate READY raw-only cleanup only if product wants that narrower policy and graph proof. Operator grants are runtime-branded from trusted config (no fake staff authority/free text/job UUID from caller). Hold stores epoch, reason enum and opaque actor; explicit hold release with CAS, no override after deletion decision.
- Consider control row for **all intents**, including unbound B2 orphans. Before declaring eligibility, freeze that intent only, lock forward and enumerate **all** raw/sanitized attempts (not just bound current generation) across the immutable target tuple. Integrate guard into B2 register/dispatch/finalize/existing receipt and C2; forbid new writes/publications/metadata after freeze under same lock. Legacy `REGISTERED` with no dispatch can retire safely under CAS; already dispatched can finish late. Scan/freeze scoped to batch, no global network lock. DB history remains; observations do not delete anything. Enforce page/cap bounds on graph (over-cap → closed/manual, not partial ledger).
- **Serial point:** local RC transaction holds ordered owner/intent/control locks, checks hold/version/eligibility using fresh DB clock then changes `OPEN → PENDING_LEDGER`, freezes graph/epoch and records durable outbox intent atomically. Hold recorded first prevents deletion; hold after committed decision returns `TOO_LATE`. This is the point of no return for the decision, **not physical erasure**. No DELETE on uncertain local or ledger COMMIT. Reconcile exact event id+namespace+epoch+target graph in fresh primary transactions. No S3/ledger network call with local DB locks or client held.
- **External ledger before DELETE:** dedicated service/role serializes append per namespace with locked head in separate primary PG volume, contiguous seq without sequence holes, canonical encoding incl item count/order + exact target/attempt/key, chain hash, idempotent eventKey on same bytes only. DB roles append/read-head only; UPDATE/DELETE/TRUNCATE records forbidden, signer key pinned out of backup. Dedicated signer issues Ed25519 signed current `namespace,seq,chainHash,challenge` from authoritative external head (challenge round trip, no accepting cached signed prefix), verify against independent trusted monotonic floor/generation; hold/governance/admin exclusion is stated, not cryptographic WORM against owner. Missing head, rewind, missing or extra record, gap, altered target, equivocation or bad signature → no DELETE/open. Tombstones only after committed ledger append, signed membership/current head proof before obtaining exact registered DELETE grants. Crash after external append but before local confirmation: recover exact entry, never invent a replacement event.
- **Delete authority:** only private worker, no arbitrary key/prefix/ListObjects-as-authority, one exact target and immutable attempt/version per grant. [Garage v2.5.0](<../infra/dev-s3/README.md#L66-L76>) has read/write bucket grants, no IAM method-scoped DELETE role/Object Lock/versioning; it cannot demonstrate separate DELETE-only credentials. Run in **new isolated synthetic namespace/bucket**, trusted verb-restricted broker or isolated worker (scope bucket credentials, deny generic client export, enforce registry+ledger claim); exact target/key allowlist confuses neither original dev credentials nor backups. Production needs tested provider-specific roles/version/delete-marker policy; `DeleteObject` 204 alone doesn't prove absence.
- Per-key append-only progress: `AUTHORIZED → DELETE_ATTEMPTED → VERIFY_PENDING → CONFIRMED_ABSENT`; aggregate is confirmed only for the entire graph. After bounded repeated verification, definitive authenticated missing **plus** evidence that all PUTs for that target/key cannot become visible later (never dispatched, or settled known write under pinned semantics, or provider-side authoritative fence). B2 has **no** such fence for arbitrary UNKNOWN. 403/timeout/ambiguous DELETE/lease expiry/client socket closed/one or repeated 404 aren't settlement. Keep permanent deny tombstone and conservative charges; reconcile late PUT with another exact-key DELETE, never serve or reuse key. Do not reset lifetime cap; release physical/live debt only by separate explicit settled records with proof; until then retain. Do not claim backup erasure or delete a DB/volume/worktree.
- **Copy-only restore:** extend [existing isolated drill](<../infra/backup/README.md#L28-L69>), which currently [does not prove atomic snapshots or file rescrub](<../infra/backup/README.md#L79-L86>). Source takes consistent DB+object synthetic snapshot at scoped write barrier or verified writer epoch (no global network freeze); signed manifest includes namespace/incarnation, migration version, DB dump SHA-256, exact DB attempt↔object inventory/byte digests, base ledger watermark, and explicitly absent/unresolved dispositions. New disposable DB + fresh private S3 target/keys with explicit signed old→new target mapping; preserve original target identities for tombstone matching, not blind endpoint rewrite. No `--clean`, no restore into existing data, no deletion of old resources. Deny all via enforced startup/control-plane barrier; if possible, skip known tombstoned objects **before** copying them. For tombstoned objects already copied, rescrub exact newly copied keys with separate restore-target grants only.
- Prove current external ledger from genesis or trusted base to signed fresh head; compare restore event/result inventories and verify copy bytes/digests. Apply lineage tombstones to DB and remapped target for **all** restored raw/sanitized/orphan attempts, permanently deny that lineage even if absent. No physical deletion precedes external append, but an unappended `PENDING_LEDGER` may already deny access in source: a complete ledger alone does not prove no such decisions. Before reopening, fence prior writers by namespace epoch, prove source pending decisions drained (or replay a separately durable decision feed) and catch up to a signed fresh head under the handoff. No source/feed proof after a disaster → deny old lineage, not «no pending decisions».
- Reopening additionally requires a signed epoch-fenced decision and live authority for old owner/cancel/session/consent/document states. Old restored auth rows alone cannot grant F access; without verified current authority, deny all old F sessions. Failure to verify active generation, head, remap or rescrub invalidates reopen. In drill: separate current primary/signer and explicit synthetic generation; demonstrate unaffected verified file and permanently denied tombstoned file, not actual live reopening.
