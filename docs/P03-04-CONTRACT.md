## Политика и основание

`policy` — полностью заданный typed reviewed snapshot из trusted configuration: versionId/sourceRef/allowedMimeTypes/maxFileBytes/maxOwnerBytes/maxOwnerFiles/expiresAt. Отсутствие/неполнота → `NOT_CONFIGURED` до любых intent/audit/outbox INSERT. Нет квот/TTL/production allowlist по умолчанию; значения тестов явно synthetic. Технический MIME-словарь `application/pdf,image/jpeg,image/png,image/webp` не разрешает загрузку/выдачу этих форматов.

Snapshot и declared bytes/MIME/expiry сохраняются неизменно. Входные `Date` policy/intent expiry копируются синхронно до первого await; исходные объекты caller не разделяются с нормализованным snapshot, хеш и SQL используют одинаковые времена. `policySha256` и `bodySha256` вычисляются сервером из canonical typed fields, а не принимаются как право. Для одного владельца один policy-version id с другим hash отклоняется. Intent не переживает policy/session expiry. PostgreSQL bigint сравнивается точно; public JS inputs допускают лишь положительные safe integers, счётчик ограничен PostgreSQL integer.

Резерв привязан к **конкретному GIVEN**, session, документу, версии и `REQUEST_PROCESSING`, с composite FK и guard. Текущий документ, отсутствие exact revoke и живой anchor обязательны. `GIVEN → revoke → новое GIVEN` не оживляет и не перепривязывает старый intent. Нет автоматического marketing/address consent.

## Транзакция, блокировки, квоты и replay

- Caller начинает **READ COMMITTED до data access** (`beginFileReservationTransaction` / `beginLegalTransaction`). Guard SET/probe/marker не доверяет session/ORM defaults; старый RR snapshot отклоняется.
- Reserve/read/replay: session `FOR UPDATE` + raw token → legal document lock/current consent → собственный intent row → повторный DB clock/anchor/policy/intent expiry после последнего ожидания → exact basis → quota/результат. Обратного file→session lock нет.
- Session lock сериализует F-owner reservations и consent revoke. Квоты включают все живые pending RESERVED count/bytes; cancelled/expired не занимают capacity. Идентичный owner/key/payload replay возвращает прежнюю запись, без второго расхода и audit/outbox. Изменённый payload → `IDEMPOTENCY_CONFLICT`; cancelled/expired не оживляется.
- Read не даёт existence oracle чужому owner. Нет object credentials, raw token/secret hash/idempotency hash/legal text в DTO. Чтение метаданных требует того же актуального basis, но само не даёт file access.
- Cancel: live raw owner → intent row → post-wait anchor clock → CAS. Новое согласие и актуальная policy/intent expiry не требуются для исторического отказа от резерва. Оба ответа — первичный и replay — только минимальная квитанция `intentId,state=CANCELLED,rowVersion,cancelledAt,replayed`: без MIME/размера/policy/consent metadata, которую обычный read в этот момент отклоняет. Повтор с current rowVersion читает terminal result без второго UPDATE; устаревший CAS отказывает. Snapshot не меняется, время и rowVersion задаёт БД.
- Intent/cancel + безопасные audit/outbox фиксируются одной caller transaction. Сбой любой записи откатывает всё. Internal writer до SQL валидирует exact nine-key shape: UUID identifiers, закрытые MIME/purpose/state, положительные safe integer bytes и PG integer rowVersion, а также operation↔state. Без URI, свободного текста и credentials; writer/helper не экспортируются из публичного index.
- DB guard отдельно проверяет RC/live/exact consent/current document/post-lock time/quota и immutable snapshot. Runtime получает SELECT 23 / INSERT 18 / UPDATE(state), без DELETE/TRUNCATE/DDL/PUBLIC или callable guards.

## Адресная доработка после вердикта Astra

- MUST 1 — исправлено: cancel возвращает отдельную минимальную квитанцию `intentId,state=CANCELLED,rowVersion,cancelledAt,replayed`, не MIME/bytes/policy/consent metadata. Это относится и к первому, и к повторному ответу после withdrawal/expiry; обычное read остаётся закрытым без актуального basis.
- MUST 2 — исправлено: Date inputs policy/intent expiry копируются синхронно до первого await; hash и INSERT используют один собственный snapshot. Caller не может изменить сохранённые значения во время ожидания lock через исходные Date references.
- MUST 3 — исправлено: internal audit writer проверяет exact shape и значения UUID/MIME/purpose/state/positive integer bytes+rowVersion; writer не экспортируется из публичного index. Короткая произвольная строка под разрешённым именем отклоняется до SQL.
- SHOULD — усилено: replay после `GIVEN → revoke → new GIVEN` повторяет тот же исходный payload/expiry и отказывает именно `CONSENT_NOT_CURRENT`, а не маскирует basis отказ изменённым payload.

**Адресное evidence:** unit **40/40**, реальная PostgreSQL suite **17/17**, API typecheck и focused lint — PASS. PG-тест после withdrawal проверяет exact keys первой и немедленно повторной cancel-квитанции и отказ read после обоих; отдельный сценарий покрывает policy/intent expiry. Date-regression наблюдает реальное ожидание session lock, меняет обе исходные Date и затем проверяет сохранённые original policy/intent expiry и оба canonical hash; replay с исходными временами успешен. SHOULD-replay использует один и тот же исходный input и ожидает ровно `CONSENT_NOT_CURRENT`.
